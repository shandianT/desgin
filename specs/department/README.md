# 部门通用设计系统

这里定义所有部门产品都可以复用的设计约束：

- 颜色、字号、间距、圆角、阴影和交互状态；
- 加载中、空数据、错误、无权限、处理中和确认反馈；
- 表单、筛选、列表、详情、页签、分页、抽屉和 AI 反馈的通用行为；
- Web、手机网页和微信小程序的语义对齐及端侧适配原则；
- 组件可访问性、键盘操作、点击区域和状态文案结构。

## 不放在这里的内容

以下内容属于产品适配层，不属于部门公共规则：

- 客户、商机、拜访、项目、任务等业务对象的字段含义；
- 某个产品的导航名称、角色、权限和接口；
- 某个产品的生产数据、数据库连接和后端状态；
- 只服务于一个产品的作战地图、销售排名或业务卡片。

## 当前迁移关系

当前规范原件仍在 `specs/salesbuddy/`，其中混合了公共规则和 SalesBuddy 业务示例。迁移期间：

- 公共规则逐步归档到本目录；
- SalesBuddy 的业务规则和示例继续留在 `specs/salesbuddy/`；
- 新产品不得复制 `specs/salesbuddy/`，应使用 `projects/<id>/project.config.json` 和自己的业务适配器；
- 迁移完成前，变更单必须标出“公共规则”还是“SalesBuddy 专属规则”。

## 组件命名

Web 组件的新代码优先使用 `Ds*` 别名，例如 `DsProvider`、`DsStatusTag` 和 `DsStatePanel`。已有 `Sb*` 导出继续保留，供 SalesBuddy 兼容使用。

小程序组件在正式改名之前，继续使用 `sb-*`，新项目接入时必须通过项目适配层登记；后续发布新的 `ds-*` 组件目录后，再切换为通用命名。
