# 小程序「客户列表 → 客户详情 → 返回」真实实现核查（frontend/miniprogram）
小程序里「客户详情」其实有三套呈现：作战地图圆点点开的底部「作战卡」浮层（selectedBattleCustomer）、客户卡片点开的全屏「客户经营详情」浮层（selectedCustomer）、以及一个在 app.json 注册但全仓库没有任何 navigateTo 跳转过去的独立页面 pages/customer-detail。前两种都是列表页内部的状态（不是新页面），所以关闭时搜索词、筛选、滚动位置天然保留，但代价是系统返回手势关不掉它们，只能点浮层里自己画的「‹」或遮罩。跨页面「打开某个客户」全部靠 wx.setStorageSync("pendingOpenCustomerId") 中转再 switchTab 回列表页，列表页 onShow 每次都重新拉三份接口，成功后才消费并删除这个键；加载失败时键不会清理，会在下次进入时意外弹出。样式层面完全没有 CSS 变量（var(-- 为 0 处），914 条 font-size 声明里 717 条小于 24rpx（即 375 宽屏下小于 12px），主色实际是 #1677FF 及十几种蓝色渐变，Web 规则里的 #2863CD / #F3F5F9 / #142F54 / #27694C / #805919 / #A73F38 在小程序里一处都没出现。tabBar 五个入口「智助 / 作战地图 / 商机 / BI / 我的」与 Web 一级导航「总览→客户→商机→拜访与跟进→任务→经营分析」在命名与对象上都不对齐，尤其「商机」tab 指向的是管理工作台页而非商机列表页。微信官方文档（developers.weixin.qq.com）被网络代理拦截，本次无法引用官方页面，凡涉及微信框架行为的判断均标为推论或未能核实。
## findings
- **[仓库证据] 详情入口一：客户卡片点击 → 列表页内全屏浮层（selectedCustomer）**
  来源：frontend/miniprogram/pages/customers/index.wxml:48（bindtap="openCustomer"）；pages/customers/index.js:340-342、383-398；index.wxml:90-165（.detail-overlay）
  openCustomer → showCustomerDetail(customerId)：wx.showLoading({title:"加载客户"}) → apiClient.getCustomer → normalizeCustomerDetail → setData({selectedCustomer}) → wx.hideTabBar。浮层是 position:fixed 的 view（index.wxss「In-page customer detail」段：.detail-overlay{position:fixed;z-index:100;...}），页面栈没有变化。
- **[仓库证据] 详情入口二：作战地图圆点点击 → 底部「作战卡」抽屉（selectedBattleCustomer），再经「查看完整客户」切到入口一**
  来源：pages/customers/index.wxml:24（catchtap="openBattleCustomer"）、56-88（.customer-sheet-layer）、86（查看完整客户）；pages/customers/index.js:357-381
  showBattleCustomer 同样调用 apiClient.getCustomer，另拼接 Agent 经营分类行（planRow）到 mapDetailRows，setData({selectedBattleCustomer}) 后 wx.hideTabBar。viewFullCustomer 先 setData({selectedBattleCustomer:null}) 再 showCustomerDetail(customer.id)——注意这里没有调用 wx.showTabBar。
- **[仓库证据] 详情入口三：独立页面 pages/customer-detail/index 已注册但全仓库无任何 navigateTo 指向它（不可达路由）**
  来源：frontend/miniprogram/app.json:12；grep 'customer-detail' 仅命中 app.json:12 及各页对 utils/customerDetail 的 require；pages/customer-detail/index.js:18-25
  页面 onLoad 读取 options.id / options.opportunityId，onShow 调 loadCustomer。仓库内 30 余处 wx.navigateTo 没有一处 url 为 /pages/customer-detail/index。它只能通过扫码/编译模式直接打开。
- **[仓库证据] 其他页面「打开某客户」都不走 navigateTo，而是写 storage 后 switchTab 回列表页，由列表页 onShow 消费**
  来源：pages/workbench/index.js:429-433；pages/opportunities/index.js:74-78；pages/index/index.js:753-758、330-334；pages/customer-edit/index.js:95-97；pages/opportunity-create/index.js:152-157；消费端 pages/customers/index.js:343-356
  写入的键有三种：pendingOpenCustomerId（工作台「查看完整客户」、商机列表行、智助卡片 open_archived_customer / open_assigned_customer、客户编辑保存后、手工商机保存后）、pendingOpenOpportunityId（商机列表、手工商机保存后，用于定位到具体商机）、pendingBattleCustomerId（智助页客户下发成功后，打开的是作战卡抽屉而非全屏浮层）。consumePendingCustomer 先看 pendingBattleCustomerId，有则 return，此时若同时存在 pendingOpenCustomerId 会残留到下一次 onShow。
- **[仓库证据] 同一客户存在三种不同的详情呈现（作战卡 / 全屏浮层 / 独立页），页签与操作项各不相同**
  来源：作战卡：pages/customers/index.wxml:56-88 + utils/customerDetail.js:260-271；全屏浮层：pages/customers/index.js:156-161（4 个页签）+ index.wxml:90-165；独立页：pages/customer-detail/index.js:11-15（3 个页签）+ index.wxml:1-74
  作战卡：CUSTOMER BATTLE CARD 眉题、名称、行业·团队、象限、风险、六维画像雷达（客户潜力/关系深度/商机成熟/拜访活跃/决策链/风险健康）、三格分数（关系等级/10、客户潜力/100、赢单概率）、10 行字段（客户名称/行业/关系等级/潜力/历史订单/日常行为/当前商机/毛利·合同/负责人/渠道生态）、建议下一步。全屏浮层：页签 经营概览/代办事项/拜访记录/商机进展，有「维护人工录入信息 编辑」「修改人工商机信息 编辑」入口，无语音记录按钮。独立页：页签 经营概览/拜访记录/商机进展（没有代办事项），头部多一个「{level}级客户」徽标，底部固定「语音记录拜访」按钮，没有任何编辑入口。
- **[仓库证据] 工作台页有一套 showCustomerCard/closeCustomerCard/openEvidence 详情浮层逻辑，但其 WXML 里 0 处绑定，属于死代码**
  来源：pages/workbench/index.js:420-433；grep -c selectedCustomer pages/workbench/index.wxml → 0；grep closeCustomerCard|viewFullCustomer|openCustomerCard|openEvidence pages/workbench/index.wxml → 无
  showCustomerCard 会 setData({selectedCustomer}) 并 wx.hideTabBar，但模板不渲染它；若未来有人给按钮绑上 openCustomerCard，tabBar 会被隐藏而屏幕上什么也不出现。
- **[仓库证据] 浮层关闭（closeCustomer / closeBattleCustomer）只清空一个字段并恢复 tabBar，keyword、activeFilter、地图六项筛选、团队/销售筛选全部原样保留**
  来源：pages/customers/index.js:399-402（closeCustomer）、372-375（closeBattleCustomer）
  closeCustomer(){ this.setData({ selectedCustomer: null }); wx.showTabBar({ animation:false }); }。没有 setData 触碰 keyword/activeFilter/mapStageIndex/selectedTeam 等。
- **[推论] 浮层模式下列表滚动位置得以保留，是因为浮层是叠在页面上的 fixed 层，页面本身没有离开**
  来源：pages/customers/index.wxss（.detail-overlay position:fixed; .detail-scroll height:calc(100vh - 88rpx)）；battle-map.wxss:163-178（.customer-sheet-layer position:fixed）
  浮层内部用自己的 scroll-view 滚动，页面 scroll 不受影响。这一点未做真机验证，属于基于代码结构的推论。
- **[仓库证据] 独立页 navigateBack 回到列表时，onShow 会无条件重新拉三份数据（客户 100 条、通讯录、商机 300 条），但不重置 keyword/activeFilter/地图筛选**
  来源：pages/customers/index.js:169-172（onShow）、173-204（loadData）、184-190（角色变化才重置团队/销售）、259（mapCustomerId 若不在新选项中回落到 all）、198（成功后 applyFilters + consumePendingCustomer）
  Promise.all([listCustomers({pageSize:100}), getDirectoryMembers(), listOpportunities({pageSize:300})])；apiClient 没有分页参数以外的 page 参数，超过 100 家客户不会显示（utils/apiClient.js:166-173）。selectedTeam/selectedMember 仅在 this.data.filterRole !== role（切换演示角色）时重置为 all。
- **[仓库证据] 列表页 onShow 同样会在从浮层内打开的子页（客户编辑、商机新建、任务创建、任务详情）返回时触发；浮层不会被清空，而是叠着重新加载**
  来源：pages/customers/index.js:410-436（从 selectedCustomer 浮层 navigateTo 到 management-task-create / task-detail / customer-edit / opportunity-create）；169-172；customer-edit/index.js:95；opportunity-create/index.js:152
  客户编辑、手工商机保存成功时会写 pendingOpenCustomerId，返回后 consumePendingCustomer → showCustomerDetail 用新数据覆盖浮层；从任务详情返回则不写键，浮层保留旧数据（selectedCustomer 未清空，也未刷新）。这两条路径体验不一致。
- **[推论] pendingOpenCustomerId 中转机制的风险：加载失败不清键、storage 持久化、无 URL 参数、多个键优先级覆盖**
  来源：pages/customers/index.js:199-203（catch 分支未 removeStorageSync）、343-356；utils/apiClient.js:19-38
  (1) loadData 失败时 catch 只 toast 并清空列表，pendingOpenCustomerId 留在 storage，下次进入作战地图 tab 会意外弹出详情；(2) wx.setStorageSync 是持久存储，小程序被杀后重开、甚至换账号登录后仍会尝试打开该客户（换账号时得到 403 toast）；(3) 打开哪个客户不体现在页面参数里，无法分享、无法回溯，违反「关键动作可追溯」；(4) pendingBattleCustomerId 优先且 return，会让同时存在的 pendingOpenCustomerId 残留一轮。
- **[仓库证据] tabBar 隐藏/显示逻辑：浮层打开时 wx.hideTabBar，关闭时 wx.showTabBar；但「作战卡 → 查看完整客户」这条链路失败时 tabBar 会永久消失**
  来源：pages/customers/index.js:369、374、376-381、395-397、401
  viewFullCustomer 关闭作战卡时没有调 showTabBar，直接 showCustomerDetail；showCustomerDetail 的 catch 只 toast「客户详情加载失败」也不恢复 tabBar。结果：抽屉已关、浮层没开、tabBar 隐藏，用户只能切到别的方式（无）——实际上会卡在没有底栏的列表页，直到再打开一次成功的详情并关闭。
- **[推论] 浮层打开时按系统返回（Android 物理返回 / iOS 边缘右滑）不会关闭浮层，因为页面栈没有变化**
  来源：pages/customers/index.json（tabBar 页，无自定义导航）；app.json:44-45；index.wxml:91（自绘「‹」按钮 bindtap="closeCustomer"）、57（遮罩 bindtap="closeBattleCustomer"）
  作战地图是 tabBar 根页面，栈深为 1。浮层只是 data 状态，微信框架不会因手势去 setData。系统返回在根页面上的行为（退出小程序 / 无响应）依赖微信平台规则，官方文档本次被代理拦截，未能核实；可确定的是代码里没有任何 onBackPress / onUnload 兜底。用户视觉上还会看到原生导航栏标题「作战地图」叠在自绘的「客户经营详情」标题栏之上（两层标题）。
- **[仓库证据] 列表页加载中 / 空数据 / 失败三种状态视觉上几乎相同：都显示「没有匹配的客户」空态，差别只在导航栏转圈和 toast**
  来源：pages/customers/index.js:175（wx.showNavigationBarLoading）、199-203（catch：visibleCustomers=[]、customers=[]、toast error.message||"客户数据加载失败"）；index.wxml:53（空态文案「没有匹配的客户 / 试试调整搜索词或筛选条件」）、23（地图空态「当前筛选范围暂无客户」）
  customers 初始为 []，首次加载期间 wx:if="{{!customers.length}}" 已为真，空态先于数据出现；失败后同样落到这个空态，文案仍提示「调整搜索词或筛选条件」，与真实原因（接口失败）不符。没有骨架屏、没有重试按钮、没有下拉刷新（未配置 enablePullDownRefresh / onPullDownRefresh / onReachBottom）。
- **[仓库证据] 失败后筛选条件在 data 里保留，但底表 visibleCustomers 被清空，所以调整筛选也只会得到空列表**
  来源：pages/customers/index.js:200-201、242-283（applyFilters 基于 this.visibleCustomers）
  keyword/activeFilter 等仍在，但 applyFilters 的输入已是 []，用户看到的仍是空态，直到下一次 onShow 重新拉数据。
- **[仓库证据] 详情加载中用 wx.showLoading；浮层失败一律 toast，不区分 403；独立页用 showModal 区分 403 并自动 navigateBack**
  来源：浮层：pages/customers/index.js:362、370、384、396；独立页：pages/customer-detail/index.js:29、44-49；错误对象来源：utils/apiClient.js:30-37、56-61
  apiClient 非 2xx 时 reject Error(message || `API 请求失败（${statusCode}）`) 并附 statusCode；401 会先刷新 token 重试一次；网络失败为「网络连接失败」。浮层 catch：toast(error.message || "客户详情加载失败")，403 时显示服务端 message 或「API 请求失败（403）」。独立页 catch：showModal({ title: statusCode===403 ? "暂无查看权限" : "客户加载失败", content: error.message || "该客户不存在或已不可见。", showCancel:false, success: () => wx.navigateBack() })。

## recommendations
- （建议）跨端样板先定「一个客户只有一种详情」：把作战卡（摘要抽屉）定义为「预览」，全屏浮层与独立页合并为唯一「客户详情」；三处的页签集合、头部字段、操作按钮统一成一张对照表写进规范，当前 代办事项页签 / 语音记录按钮 / 编辑入口 三者分散在不同实现里。
- （建议）手机端「列表→详情→返回」改为真实页面栈：列表卡片 navigateTo('/pages/customer-detail/index?id=…&opportunityId=…')，返回靠系统手势与导航栏返回，onShow 只在有变更标记时局部刷新；作战地图圆点保留底部抽屉作为预览，抽屉内「查看完整客户」再 navigateTo。这样才能对应 Web 的「导航—列表—详情」三段式：手机上是「列表页 → 详情页」两级栈，而不是同页浮层。
- （建议）废弃 pendingOpenCustomerId / pendingOpenOpportunityId / pendingBattleCustomerId 的 storage 中转：跨 tab 打开客户用 wx.navigateTo 直达详情页（详情页不是 tab 页，可直接跳），需要回到列表时再 switchTab；若短期保留，至少在 loadData 的 catch 与 onHide 里清键，并给键加时间戳过期。
- （建议）在规范里写明「浮层/抽屉不得替代页面级返回」的规则：任何隐藏 tabBar 的全屏浮层必须成对出现 hideTabBar/showTabBar，且失败路径必须恢复（当前 viewFullCustomer → showCustomerDetail 失败会把 tabBar 永久藏起来）。
- （建议）字号底线落地为 lint：规范要求正文 ≥14px、说明 ≥12px，对应 rpx 就是正文 ≥28rpx、说明 ≥24rpx；现在 88% 的声明不达标，建议先在样板三文件（customers/index.wxss、battle-map.wxss、customer-detail/index.wxss）整改并加一个 grep 脚本作为 CI 检查（阈值：font-size < 24rpx 即失败）。
- （建议）颜色与间距集中维护：在 app.wxss 的 page 选择器上定义 CSS 变量（--color-primary:#2863CD;--color-bg:#F3F5F9;--color-success:#27694C;--color-warning:#805919;--color-danger:#A73F38;--space-1:8rpx…），页面 wxss 只允许 var(--…)；由同一份 tokens.json 生成 Web 的 :root 变量与小程序的 page 变量，这就是「集中维护并同步到各端」最省事的机制。先决定主色到底是 #2863CD 还是小程序现用的 #1677FF。
- （建议）状态表达统一：列表加载中用骨架或「加载中」占位而不是先显示空态；失败态给出「加载失败 · 重试」并保留筛选；403 在浮层与独立页统一用 showModal「暂无查看权限」；拜访记录补空态文案。
- （建议）术语统一：tab 名、导航栏标题、页面大标题对同一对象只用一个词（建议「客户」），「客户资产」只保留为象限名；tab「商机」要么改指向 pages/opportunities，要么改名「工作台」；商机阶段档位与概率按项目口径（10/30/50/70/90 ↔ 识别/验证/方案/谈判/签约）在 utils/customerDetail.js 与两个页面的 stages 数组同时修正。
- （建议）负责人字段按项目原则显示地盘 ID（可附人名），列表行补「当前商机名称/金额」以体现「客户下面挂商机」。
