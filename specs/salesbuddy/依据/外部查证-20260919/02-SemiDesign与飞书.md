Semi Design 官网（semi.design）与飞书全部官方域名（open.feishu.cn、www.feishu.cn、larksuite.com、larkoffice.com）在本次会话被网络出口策略拦截，无法直接打开；但 Semi 的官网文档与主题源码全部公开在官方仓库 github.com/DouyinFE/semi-design（本次克隆到 main 分支 82c5389，2026-09-17），因此关于 Semi 的结论均引自官方仓库源文件，可视为官方事实；关于飞书客户端「导航—列表—内容」布局与移动端规范的内容全部标为「未能核实」。Semi 把设计变量分成三层：原始色盘（--semi-blue-5 这类「基础色」）→ 语义功能色（--semi-color-primary 这类「功能色」，用 CSS 变量承载，因为要在运行时切换明暗）→ 组件变量（$color-button_primary-bg-default 这类 Sass 变量，编译期固定，指向上一层）；尺寸、间距、字号、z-index 只用 Sass 变量（$spacing-base: 16px 等），不输出 CSS 变量。主题定制走 DSM（Design System Manager，Semi 的可视化主题编辑站）生成 npm 主题包，再由 webpack／vite 插件按「npm 主题包 < 本地 scss < 插件参数」的优先级覆盖变量，Figma 端通过 Semi Toolbox 插件同步同一主题。Semi 官方明确「暂无计划」做移动端组件库，也没有小程序版本，其响应式能力只有 Grid／Layout.Sider 的六档断点（xs<576、sm≥576、md≥768、lg≥992、xl≥1200、xxl≥1600），且官方文档自述尚不支持「媒体查询」变量。因此，Semi 能教给本部门的是「语义变量分层 + 主题包 + 设计工具同步」这一套维护方法，而不是跨端布局规则；「飞书移动端怎么组织列表与详情」这一问在本次无法用官方页面回答。

- **[官方事实] Semi 颜色变量分两层：「基础色」原始色盘（16 色相 × 10 级 = 160 色）与从中引用的「功能色」（语义色）**
  来源：content/basic/tokens/index.md:24-26；packages/semi-theme-default/scss/_palette.scss:1-80；packages/semi-theme-default/scss/global.scss:3-12
  文档原文：「基于品牌色动态生成，包含 160 个颜色在内的，16 个不同色相的梯度色盘。通常情况下，我们用使用基础色中的颜色来进一步定义功能色。你可以在 Semi DSM 配置你的产品品牌色，动态生成新的基础色盘。」代码写法：_palette.scss 中基础色以「无 rgba 包裹的三元组」声明，如 `--semi-blue-5: 0,100,250;`、`--semi-grey-9: 28,31,35;`；global.scss 中功能色引用基础色并补透明度，如 `--semi-color-primary: rgba(var(--semi-blue-5), 1);`、`--semi-color-primary-hover: rgba(var(--semi-blue-6), 1);`、`--semi-color-primary-active: rgba(var(--semi-blue-7), 1);`、`--semi-color-primary-disabled: rgba(var(--semi-blue-2), 1);`、`--semi-color-primary-light-default: rgba(var(--semi-blue-0), 1);`。这种「三元组 + rgba()」写法让同一色阶可派生不同透明度（例如 `--semi-color-text-1: rgba(var(--semi-grey-9), .8)`）。
- **[官方事实] Semi 语义色的命名规则是 --semi-color-{语义}-{状态}，语义共 7 类功能色 + 文本／背景／填充／描边／禁用／链接等分组**
  来源：packages/semi-theme-default/scss/global.scss:8-95；content/basic/tokens/index.md:36-140
  语义分组（文档标题原文）：主要颜色 primary、次要颜色 secondary、第三颜色 tertiary、信息 info、成功 success、警示 warning、危险 danger、AI general／purple／background、文本与图标颜色 text、链接色 link、背景色 bg、填充色 fill、描边色 border、禁用态 disabled、常量色 static、拟阴影色 shadow。状态后缀：默认（无后缀）／-hover／-active／-disabled，浅版为 -light-default／-light-hover／-light-active。分级变量用数字：`--semi-color-text-0`（最主要，rgba(grey-9,1)）、`-text-1`（.8）、`-text-2`（.62）、`-text-3`（.35）；`--semi-color-bg-0`～`-bg-4`（最下层页面 → 最上层特殊，注释：「在暗色模式下，我们通常用背景色来区分前后层级」）；`--semi-color-fill-0/1/2`（默认／悬浮／激活，rgba(grey-8, .05/.09/.13)）；`--semi-color-border: rgba(var(--semi-grey-9), .08)`；`--semi-color-nav-bg`（导航背景色）；`--semi-color-overlay-bg: rgba(22,22,26,.6)`。圆角：`--semi-border-radius-extra-small: 3px`、`-small: 3px`（button/tag/tabs）、`-medium: 6px`（dropdown 等菜单）、`-large: 12px`（modal）、`-circle: 50%`、`-full: 9999px`。阴影：`--semi-shadow-elevated: 0 0 1px rgba(0,0,0,.3), 0 4px 14px rgba(0,0,0,.1)`。
- **[官方事实] Semi 官方分层原则：不需要运行时切换的变量用 Sass 变量承载；需要运行时切换（如暗色相关颜色）的用 CSS 变量承载**
  来源：packages/semi-theme-default/README.md:27-30（Design Token stratification principle）及目录说明 README.md:12-23
  原文：「No need to switch at runtime, carried by sass variable」「Need to support runtime switching, such as the color variable related to the dark mode, carried by css variable」。目录职责：`_palette.scss // Global original color palette(css variable)`、`global.scss // Global Design Token(css variable, including light and dark mode)`、`variables.scss // Sizing,spacing,zindex and font related design token`、`_font.scss // Font-related scss mixin`、`mixin.scss // Extra mixin(e.g, shadow)`。推论提示：这意味着 Semi 的字号、间距不是运行时 CSS 变量，跨端若要共享这些值，需要从 Sass 源再导出，而非直接读 CSS 变量。

- **[官方事实] 插件实现上，覆盖变量的方法是把 local.scss／参数插到组件样式 `@import './variables.scss'` 之后再编译，所以 Sass 变量必须在编译期确定**
  来源：packages/semi-webpack/src/semi-theme-loader.ts:10-49
  代码：`const scssVarStr = \`@import "~${theme}/scss/index.scss";\n\``（每个组件样式都注入）、`const cssVarStr = \`@import "~${theme}/scss/global.scss";\n\``（只注入一次）；当存在 include/variables/local.scss 时，用正则 `/(@import '.\/variables.scss';?|@import ".\/variables.scss";?)/g` 切分源码并把 `localImport` 拼在组件 variables 之后。推论：这就是 Semi「主题包 = 一组 Sass 变量覆盖 + 一份 CSS 变量表」的落地方式；换到小程序（WXSS）时只能复用 CSS 变量那一份，Sass 层需要另行编译输出。
- **[官方事实] 暗色模式与局部主题的切换方式：body[theme-mode="dark"] 挂第二套色盘；.semi-always-dark／.semi-always-light 局部强制；同时支持 Shadow DOM 的 :host**
  来源：content/advanced/dark-mode/index.md:22-40,100-104；packages/semi-theme-default/scss/global.scss:3,146；packages/semi-theme-default/scss/_palette.scss:1,240
  文档原文：「Semi 暗色模式的切换是通过给 body 添加属性 [theme-mode='dark'] 来实现的（我们在 body 下同时挂载了两套色盘）」「推荐你在 body 上配置 color、background-color……自适应亮/暗色切换」：`body { color: var(--semi-color-text-0); background-color: var(--semi-color-bg-0); }`。「Semi 2.0 原生支持局部暗色/亮色模式。使用时，在顶级元素上添加 .semi-always-dark 或 .semi-always-light 类」；注意「弹出层默认是插入到 body 中，局部暗色/亮色对弹出层元素不生效」。选择器原文：`body, body[theme-mode="dark"] .semi-always-light, :host, :host .semi-always-light {…}` 与 `body[theme-mode="dark"], body .semi-always-dark, :host([theme-mode="dark"]), :host .semi-always-dark {…}`。暗色下语义变量重新指向：`--semi-color-bg-0: rgba(22,22,26,1)`、`-bg-1: rgba(35,36,41,1)`、`-bg-2: rgba(53,54,60,1)`、`--semi-color-border: rgba(var(--semi-white), .08)`；而 `--semi-color-primary` 仍是 `rgba(var(--semi-blue-5),1)`，靠 _palette.scss 中暗色版 `--semi-blue-*` 三元组反转来变色。

## recommendations
- （建议）变量分三层，照搬 Semi 的命名骨架但改前缀：第一层原始色盘 `--sb-blue-5: 40,99,205;`（三元组，来自主色 #2863CD），第二层语义变量 `--sb-color-primary: rgba(var(--sb-blue-5), 1)`、`--sb-color-primary-hover`、`--sb-color-primary-active`、`--sb-color-primary-disabled`、`--sb-color-primary-light-default`，第三层组件变量只准引用第二层（如 `--sb-button-primary-bg: var(--sb-color-primary)`）。现有侧栏 #142F54、工作区 #F3F5F9 分别落到 `--sb-color-nav-bg`、`--sb-color-bg-0`，避免各端各自写死。
- （建议）与 Semi 不同，本部门把字号、间距、圆角、层级也做成 CSS 变量而不是仅 Sass 变量，因为小程序 WXSS 和移动 H5 只能共享 CSS 变量：`--sb-spacing-1: 4px … --sb-spacing-6: 32px`（对应已确认的 4/8/12/16/24/32）、`--sb-font-size-small: 12px`、`--sb-font-size-regular: 14px`、`--sb-font-size-h6: 16px`、`--sb-font-size-h3: 24px`、`--sb-font-size-h1: 32px`，并像 Semi 的 _font.scss 一样为每档字号绑定行高（12/16、14/20、16/22、24/32、32/44）。
- （建议）建立「单一事实来源」文件 tokens.json（或 tokens.css），由脚本生成三份产物：Web 用的 `:root{}`、小程序用的 `page{}`、Figma 变量导入文件；参照 Semi「DSM 发布 npm 主题包 → 插件接入」的思路，把生成物做成一个内部 npm 包（如 `@dept/design-tokens`），三端只允许安装该包，不允许手抄数值。这一条是对 Semi 做法的类比迁移，Semi 本身没有小程序产物。
- （建议）明暗与局部主题的机制直接借用 Semi 写法：Web 用 `body[theme-mode="dark"]` 挂第二套变量、`.sb-always-light/.sb-always-dark` 做局部强制；小程序对应 `page[data-theme="dark"]`。先只定义机制、不急于产出暗色值。
- （建议）响应式断点写进规范时标明与 Semi 的差异：本部门三档（>900 / 601～900 / ≤600）比 Semi 六档少，建议保留三档但把 600 与 Semi 的 sm(576)／md(768) 对齐说明，避免以后引入 Semi 组件时两套断点打架；另外 Semi 文档明确「不支持媒体查询变量」，本部门可把断点也做成变量（`--sb-bp-mobile: 600px`）但注明 CSS 媒体查询不能直接引用 CSS 变量，需要由构建脚本注入。
- （建议）「导航—列表—详情」三段布局在手机上的组织方式，本次没有拿到飞书官方页面依据，不要在规范中写「参考飞书」；应改为在本部门的「客户列表→详情→返回」样板里实际验证后再写规则。Semi 唯一可引用的是 Layout.Sider 的 `breakpoint`／`onBreakpoint` 机制（窄屏收起侧栏，240px → 60px）。
- （建议）把 Semi FAQ 的口径写进团队协作章节：全局 Token 改动 = 品牌级、全局生效、走变更流程；某模块局部微调 = CSS 覆盖、不动 Token。并沿用 Semi「新增通用变量会在更新日志标注，主题需重新发布」的做法：tokens 包每次发版附 CHANGELOG，三端升级依赖即同步。
- （建议）待能访问 open.feishu.cn 时，优先复核三页：响应式设计指南、字体、小程序设计规范中的导航（gadget-design-specification/visual-specifications/navigation），再决定字号下限与点击区域规则是否与飞书对齐。
