# Ant Design 体系（Web / H5 / 小程序）设计变量维护方式查证
查证结论：Ant Design 三个端并没有一套共享的「token 源」或同步机制，而是三套各自独立的变量系统。Web 端 antd 5 用「Seed → Map → Alias」三层 Design Token（在 JS 里算出来，可选导出为 --ant-* CSS 变量）；手机 H5 端 antd-mobile 直接在 :root 写一套 --adm-* CSS 变量，没有派生算法；小程序端 antd-mini 用 :root, page 写一套 --color-*/--size-* 全局变量加 --button-* 组件变量，尺寸单位一律 rpx。三端变量名不一致（colorPrimary / --adm-color-primary / --color-brand1），默认值也不一致（Web 字号基准 14px，H5 主字号 13px，小程序 28rpx=14px）。「基础档位 → 用途命名 → 端侧映射」的三层思路在 Web 端 antd 5 是官方明确定义的成熟做法，但把三层贯通到 H5 和小程序，是我们部门要自己搭的桥，Ant Design 官方没有替我们做。说明：ant.design、mobile.ant.design、mini.ant.design 三个官网域名在本环境被网络代理拦截，本报告所有「官方事实」均来自这三个项目 GitHub 官方仓库中生成官网页面的源文件与源代码（raw.githubusercontent.com），已逐一打开核对。
## findings
- **[官方事实] antd 5 官方把 Design Token 明确定义为三层派生关系：Seed Token（基础变量）→ Map Token（梯度变量）→ Alias Token（别名变量）。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/docs/react/customize-theme.zh-CN.md（即 https://ant.design/docs/react/customize-theme-cn 的源文件；官网域名被代理拦截，未能直接打开）
  原文：「在 Design Token 中我们提供了一套更加贴合设计的三层结构，将 Design Token 拆解为 Seed Token、Map Token 和 Alias Token 三部分。」「这三组 Token 并不是简单的分组，而是一个三层的派生关系，由 Seed Token 派生 Map Token，再由 Map Token 派生 Alias Token。」定义：「Seed Token 意味着所有设计意图的起源」（例 colorPrimary: '#1890ff'）；「Map Token 是基于 Seed 派生的梯度变量」（例 colorPrimaryBg: '#e6f7ff'）；「Alias Token 用于批量控制某些共性组件的样式，基本上是 Map Token 别名，或者特殊处理过的 Map Token」（例 colorLink）。名词解释：Design Token = 把颜色、字号、间距等设计决定写成带名字的变量。
- **[官方事实] Seed Token 的官方默认值（可直接当「基础档位」参照）：colorPrimary #1677ff、colorSuccess #52c41a、colorWarning #faad14、colorError #ff4d4f、fontSize 14、sizeUnit 4、sizeStep 4、controlHeight 32、borderRadius 6、lineWidth 1、zIndexPopupBase 1000、motionUnit 0.1。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/seed.ts 与 https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/interface/seeds.ts
  seeds.ts 的 JSDoc：sizeUnit「用于控制组件尺寸的变化单位，基础单位为 4」；sizeStep「用于控制组件尺寸的基础步长」；fontSize「设计系统中使用最广泛的字体大小」默认 14；controlHeight「按钮和输入框等基础控件的高度」默认 32；colorTextBase「用于派生文本色梯度的基础变量」；colorBgBase「用于派生背景色梯度的基础变量」。Seed 层非常少（约 30 个），说明「基础档位」层应该刻意保持精简。
- **[官方事实] Map Token 的间距梯度是用公式从 Seed 算出来的：sizeXXS 4、sizeXS 8、sizeSM 12、size/sizeMS 16、sizeMD 20、sizeLG 24、sizeXL 32、sizeXXL 48（sizeUnit=4、sizeStep=4 时）。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/shared/genSizeMapToken.ts
  公式：sizeXXL = sizeUnit×(sizeStep+8)；sizeXL = sizeUnit×(sizeStep+4)；sizeLG = sizeUnit×(sizeStep+2)；sizeMD = sizeUnit×(sizeStep+1)；size = sizeUnit×sizeStep；sizeSM = sizeUnit×(sizeStep−1)；sizeXS = sizeUnit×(sizeStep−2)；sizeXXS = sizeUnit×(sizeStep−3)。本部门已确认的 4/8/12/16/24/32px 间距档与 antd 的 4/8/12/16/24/32 完全重合（antd 多一档 20 和 48）。
- **[官方事实] Map Token 的字号梯度也是算出来的：fontSizeSM 12、fontSize 14、fontSizeLG 16、fontSizeXL 20、fontSizeHeading5 16、H4 20、H3 24、H2 30、H1 38；行高公式 (fontSize+8)/fontSize。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/shared/genFontSizes.ts 与 https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/shared/genFontMapToken.ts
  源码：baseSize = base × e^(i/5)，i = index−1，取整后向下取偶数，fontSizes[1] = base；lineHeight = (fontSize + 8) / fontSize。本人用 Python 按源码公式在 base=14 下复算得到序列 [12,14,16,20,24,30,38,46,56,68]；genFontMapToken 映射 fontSizeSM=[0]、fontSize=[1]、fontSizeLG=[2]、fontSizeXL=[3]、Heading5=[2]、Heading4=[3]、Heading3=[4]、Heading2=[5]、Heading1=[6]。本部门 12/14/16/24/32 字号档中 12/14/16/24 与 antd 一致，32 不在 antd 梯度里（antd 是 30）。
- **[官方事实] Map Token 的颜色梯度：主色由 @ant-design/colors 的 generate() 生成 10 档色板，colorPrimaryBg 取第 1 档、colorPrimaryBorder 第 3 档、colorPrimaryHover 第 5 档、colorPrimary 第 6 档、colorPrimaryActive 第 7 档、colorPrimaryText 第 9 档；中性色由透明度派生：colorText 0.88、colorTextSecondary 0.65、colorTextTertiary 0.45、colorTextQuaternary 0.25。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/shared/genColorMapToken.ts 与 https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/themes/default/colors.ts
  genColorMapToken：colorPrimaryBg=[1]、BgHover=[2]、Border=[3]、BorderHover=[4]、Hover=[5]、Primary=[6]、Active=[7]、TextHover=[8]、Text=[9]、TextActive=[10]；colorLinkHover=[4]、colorLink=[6]、colorLinkActive=[7]。colors.ts：colorText=getAlphaColor(colorTextBase,0.88)，Secondary/Tertiary/Quaternary=0.65/0.45/0.25；colorFill=0.15，Secondary/Tertiary/Quaternary=0.06/0.04/0.02；colorBgContainer/Elevated=getSolidColor(colorBgBase,0)，colorBgLayout=getSolidColor(colorBgBase,4)，colorBorder=getSolidColor(colorBgBase,15)，colorBorderSecondary=getSolidColor(colorBgBase,6)。含义：只要改 Seed 的 colorPrimary（如本部门 #2863CD），10 档梯度自动重算。
- **[官方事实] Alias Token（用途命名层）的派生规则：paddingXXS…paddingXL 直接等于 sizeXXS…sizeXL，marginXXS…marginXXL 同理；colorTextPlaceholder/colorTextDisabled = colorTextQuaternary；colorTextHeading = colorText；colorTextLabel = colorTextSecondary；colorIcon = colorTextTertiary；colorBgContainerDisabled = colorFillTertiary；fontSizeIcon = fontSizeSM；fontWeightStrong 固定 600；screenXS…screenXXL 断点带 Min/Max 变体。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/util/alias.ts 与 https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/interface/alias.ts
  alias.ts JSDoc 描述举例：colorFillContent「Background color of content area」；colorSplit「Separator Color」；colorTextPlaceholder「Placeholder Text Color」；colorTextHeading「Heading Text Color」；colorIcon「Weak action icon color」；controlOutline「Input component outline color」。这一层名字全是「用途」而不是「颜色本身」，是「用途命名」层的官方范例。
- **[官方事实] Map Token 中的核心语义色（可直接对应本部门「工作区背景 #F3F5F9」等用途）：colorBgLayout「页面整体布局的背景色，只用于 B1 视觉层级」、colorBgContainer「容器背景色，如默认按钮、输入框」、colorBgElevated「弹层容器背景色」、colorBgMask「遮罩背景色」、colorBorder「默认边框色」、colorBorderSecondary「比默认边框色稍浅，等于 colorSplit」。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/components/theme/interface/maps/colors.ts
  JSDoc 原文（英文）：colorBgLayout「Color used for the background color of the overall layout of the page. Only used when at the B1 visual level in the page.」colorBgContainer「Container background color, e.g: default button, input box, etc. Be sure not to confuse this with colorBgElevated.」colorTextSecondary「Second level of text color generally used in scenarios where text color is not emphasized, such as label text」。
- **[官方事实] antd 5 通过 ConfigProvider 的 theme 属性定制主题：token 改 Seed/Map/Alias，components 改单组件，algorithm 组合暗色/紧凑算法；ConfigProvider 可嵌套，子主题未改的 token 继承父主题；非 React 场景用 theme.getDesignToken() 取 token。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/docs/react/customize-theme.zh-CN.md
  代码：const theme = { token: { colorPrimary: '#1890ff' } }；theme.components.Button 覆盖「该组件消费的 Alias Token」；import { theme } from 'antd'; const { darkAlgorithm, compactAlgorithm } = theme; { algorithm: [darkAlgorithm, compactAlgorithm] }。原文：「可以嵌套使用 ConfigProvider 来实现局部主题的更换。在子主题中未被改变的 Design Token 将会继承父主题」；getDesignToken 用于「非 React 生命周期消费 Token 变量」：const globalToken = getDesignToken(config)。另有官方「主题编辑器」（/theme-editor）可视化调 token。
- **[官方事实] antd 5 可以把 token 导出为 CSS 变量：theme={{ cssVar: true }}，变量名格式为 --ant-<token 的 kebab-case>（如 colorPrimary → --ant-color-primary），前缀默认 ant（与 prefixCls 一致），可配 cssVar.prefix / cssVar.key。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design/master/docs/react/customize-theme.zh-CN.md（cssVar API 表）；命名转换源码 https://github.com/ant-design/cssinjs/blob/master/src/util/css-variables.ts（token2CSSVar）
  文档 API 表：cssVar「CSS 变量配置」；prefix「CSS 变量的前缀，默认与 ConfigProvider 上配置的 prefixCls 相同」默认 ant；key「当前主题的唯一识别 key，默认用 useId 填充」；hashed「将样式添加至 hash className 上」，用 CSS 变量时建议 hashed: false。cssinjs 源码：token2CSSVar = (token, prefix='') => `--${prefix ? prefix+'-' : ''}${token}`.replace(/([a-z0-9])([A-Z])/g,'$1-$2')…，即驼峰转短横线。这是把「JS 里的 token」输出成「浏览器 CSS 变量」的官方桥梁。
- **[官方事实] antd-mobile（手机 H5）的主题机制是纯 CSS 变量：全局变量以 --adm- 为前缀，直接声明在 :root 下；覆盖时官方要求写 :root:root 提高优先级；局部主题在任意节点类名上覆盖即可。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mobile/master/docs/guide/theming.zh.md（即 https://mobile.ant.design/zh/guide/theming 的源文件；官网域名被代理拦截）
  原文：「由于 antd-mobile 中的主题变量也是在 :root 下声明的，所以在有些情况下会由于优先级的问题无法成功覆盖。通过 :root:root 可以显式地让你所写内容的优先级更高一些」。代码：:root:root { --adm-color-primary: #a062d4; } 与 .purple-theme { --adm-color-primary: #a062d4; }。文档另提示 5.14.0 起 --adm-border-color 弃用，改用 --adm-color-border。名词解释：CSS 变量 = 在样式表里用 --名字 定义、用 var(--名字) 引用的值，浏览器原生支持，改一处全局生效。
- **[官方事实] antd-mobile 全局变量清单与默认值（浅色）：--adm-color-primary #1677ff、--adm-color-success #00b578、--adm-color-warning #ff8f1f、--adm-color-danger #ff3141、--adm-color-text #333333、--adm-color-text-secondary #666666、--adm-color-weak #999999、--adm-color-light #cccccc、--adm-color-border #eeeeee、--adm-color-box #f5f5f5、--adm-color-background #ffffff、--adm-font-size-1～10 = 9～18px、--adm-font-size-main 13px、--adm-radius-s/m/l 4/8/12px。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mobile/master/src/global/theme-default.less
  字号十档：--adm-font-size-1: 9px … --adm-font-size-10: 18px，--adm-font-size-main = var(--adm-font-size-5) = 13px；--adm-color-fill-content = var(--adm-color-box)；文件里没有间距变量（没有 --adm-spacing-*），没有派生算法，每个值都是手写的常量。注意 antd-mobile 的 success 色 #00b578、warning 色 #ff8f1f 与 Web 端 antd 的 #52c41a、#faad14 不同。
- **[官方事实] antd-mobile 深色模式：在 html 标签加 data-prefers-color-scheme="dark"，内部就是同名 --adm-* 变量换一套值（如 --adm-color-primary #3086ff、--adm-color-text #e6e6e6、--adm-color-background #1a1a1a）；官方标注为试验阶段。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mobile/master/docs/guide/dark-mode.zh.md 与 https://raw.githubusercontent.com/ant-design/ant-design-mobile/master/src/global/theme-dark.less
  原文：「antd-mobile 内置了一套深色模式的主题，你只需要在页面的 html 标签上设置属性 data-prefers-color-scheme="dark" 即可启用」；JS：document.documentElement.setAttribute('data-prefers-color-scheme','dark')。theme-dark.less 选择器 html[data-prefers-color-scheme='dark'] 下共 16 个变量，含 --adm-color-primary #3086ff、success #34b368、warning #ffa930、danger #ff4a58、text #e6e6e6、text-secondary #b3b3b3、weak #808080、light #4d4d4d、border #2b2b2b、box #0a0a0a、background #1a1a1a。
- **[官方事实] antd-mobile 的组件级变量有两层命名：组件内部短名（--border-radius、--border-width，写在组件 style 或类名上）与全局长名（--adm-button-border-radius 这种 --adm-[组件]-[属性] 格式，写在 :root）。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mobile/master/docs/guide/css-variables.zh.md；按钮源码 https://github.com/ant-design/ant-design-mobile/blob/master/src/components/button/button.less
  文档给出三种方式：类名 + CSS 文件；「直接通过组件的 style 属性」（「简单粗暴，适合小范围的调整」）；在 :root 写 --adm-button-border-radius 等全局变量。button.less 中 &-primary { --color: var(--adm-color-primary); }，说明组件短名变量最终引用全局 --adm-* 变量。iOS 9 等不支持 CSS 变量的环境可引入 antd-mobile/bundle/css-vars-patch.css 降级，但会失去主题与深色模式。
- **[官方事实] antd-mini（小程序）主题机制也是 CSS 变量，声明在 :root, page 两个选择器下；全局变量前缀是 --color-*、--size-*、--opacity-*（没有 ant/adm 前缀），组件变量前缀是 --button-*、--actionsheet-* 等。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mini/master/src/style/variables.less；文档 https://raw.githubusercontent.com/ant-design/ant-design-mini/master/docs/guide/customize-theme.md（即 https://mini.ant.design/guide/customize-theme 的源文件；官网域名被代理拦截）
  variables.less 开头：:root, page { --color-brand1: #1677ff; --color-brand1-faded: rgba(22,119,255,0.1); --color-brand2: #1677ff; --color-link: #4b6b99; --color-orange: #ff6430; --color-yellow: #ff9f18; --color-green: #22b35e; … }；文本色 --color-text-primary #333333、--color-text-secondary #666666、--color-text-assist #999999、--color-text-weak #cccccc；--color-border #eeeeee；--color-background #f5f5f5；--color-card #ffffff。文档原文：「定制使用的 CSS 变量名称可以在每个组件的文档里查看，或者在配置文件查看完整版便变量名称」；「在 app.less 中，写入 CSS 变量，即可对全局生效」（示例写在 page 选择器下）；三种覆盖位置：单组件类名、容器节点（「用一个 configProvider 或任意容器节点（比如 ant-container）包裹住需要定制的组件」）、全局 page。
- **[官方事实] antd-mini 尺寸类变量一律用 rpx：--size-font1～12 = 22/24/26/28/30/32/34/36/40/48/56/64rpx；--size-radius-xs～xxl = 8/16/24/32/40/48rpx；--size-space1 4rpx、--size-space-page-margin 16rpx；Less 侧定义 @rpx: 1rpx、@size-base: 8 * @rpx，组件样式写成 24 * @rpx。**
  来源：https://raw.githubusercontent.com/ant-design/ant-design-mini/master/src/style/variables.less 与 https://github.com/ant-design/ant-design-mini/blob/master/src/style/themes/index.less；组件示例 https://github.com/ant-design/ant-design-mini/blob/master/src/Card/index.less
  themes/index.less 原文：「// @hd: 1px; // @rpx: 0.5 * @hd; @rpx: 1rpx; @size-base: 8 * @rpx;」——注释说明作者曾考虑 px 方案，最终选 rpx。Card/index.less：border-radius: 24 * @rpx; padding: 24 * @rpx。Button 文档示例：.custom-size { font-size: 22rpx; }。名词解释：rpx = 小程序的「响应像素」，规定屏幕宽度恒等于 750rpx，在 375pt 宽的 iPhone 上 2rpx = 1px（px 这里指 CSS 逻辑像素），所以 28rpx ≈ 14px、24rpx ≈ 12px、32rpx ≈ 16px。CHANGELOG 有「Feat/rpx #21」记录，说明 rpx 是早期即定下的方案。
- **[官方事实] antd-mini 的 ConfigProvider 支持 theme="light|dark" 与 themeVars 对象；themeVars 的 key 不写 -- 前缀，组件内部自动转 kebab-case 并加 --，输出成容器的内联 style。深色模式默认跟随系统 prefers-color-scheme。**

- **[推论] 三端同一语义的变量名与默认值对照（官方原值）：主色 colorPrimary / --adm-color-primary / --color-brand1，均为 #1677ff；正文色 colorText=rgba(0,0,0,0.88) / --adm-color-text #333333 / --color-text-primary #333333；次要文字 colorTextSecondary=rgba(0,0,0,0.65) / --adm-color-text-secondary #666666 / --color-text-secondary #666666；边框 colorBorder(#d9d9d9 级) / --adm-color-border #eeeeee / --color-border #eeeeee；页面底色 colorBgLayout(#f5f5f5 级) / --adm-color-box #f5f5f5 / --color-background #f5f5f5；容器底色 colorBgContainer #fff / --adm-color-background #ffffff / --color-card #ffffff；基准字号 fontSize 14px / --adm-font-size-main 13px / --size-font4 28rpx(≈14px)。**
  来源：综合上述各源文件：seed.ts、colors.ts、theme-default.less、variables.less
  这是把三套官方值按「用途」手工对齐的结果，官方没有给这张表。可以看出：H5 与小程序两端（都是蚂蚁移动系）的中性色值相互一致（#333/#666/#999/#ccc/#eee/#f5f5f5），但与 Web 端 antd 的透明度派生体系不一致；H5 主字号 13px 而 Web 与小程序都是 14px；成功/警告色三端各异（Web #52c41a/#faad14，H5 #00b578/#ff8f1f，小程序 --color-green #22b35e / --color-yellow #ff9f18）。变量命名风格也是三套：Web 驼峰 JS 名（可选导出 --ant-*），H5 --adm-*，小程序无前缀 --color-*。
- **[推论] 「基础档位 → 用途命名 → 端侧映射」三层是成熟做法：前两层与 antd 5 官方的 Seed（基础）→ Map（梯度）/Alias（用途别名）完全对应；第三层「端侧映射」在 Ant Design 体系里只在 Web 端有官方实现（token → --ant-* CSS 变量），跨到 H5/小程序没有官方实现，需要部门自建。**
  来源：综合 antd customize-theme 文档、cssinjs token2CSSVar、antd-mobile theming、antd-mini variables.less
  依据：1) antd 官方明确说三层是「派生关系」而非分组，与「基础档位派生用途命名」思路一致；2) antd 的 Alias 层名字全是用途（colorTextPlaceholder、colorBgContainerDisabled、paddingSM），证明「用途命名」层应独立于色值；3) H5 和小程序两端都只有「一层扁平 CSS 变量」，没有派生层，因此部门若要三端同步，只能在自己的源文件里做派生，再分别「输出」成 --ant-*（Web，或直接喂 ConfigProvider token）、--adm-*（H5）、--color-*/--button-*（小程序）三种目标名。
- **[推论] 三端变量名不一致，且官方无意统一。**
  来源：综合上述 seed.ts / theme-default.less / variables.less 及三份主题文档
  证据：同一个「主色」在三端叫 colorPrimary、--adm-color-primary、--color-brand1；同一个「页面底色」叫 colorBgLayout、--adm-color-box、--color-background；「容器底色」叫 colorBgContainer、--adm-color-background、--color-card——注意 --adm-color-background 与 --color-background 名字相同但含义不同（H5 指白色容器，小程序指灰色页面底），这是跨端复用时最容易踩的坑。三个仓库互不引用对方变量文件，也没有共享 npm 包。
- **[未能核实] ant.design、mobile.ant.design、mini.ant.design 三个官网页面本身未能直接打开（含任务指定的 https://ant.design/docs/react/customize-theme-cn#seedtoken）。**
  来源：WebFetch 返回 EGRESS_BLOCKED：「Access to ant.design is blocked by the network egress proxy」，mobile.ant.design、mini.ant.design、ant-design.antgroup.com 同样被拦截
  替代做法：三站官网页面均由各自 GitHub 仓库的 docs/ 目录 Markdown 生成，本报告改读 raw.githubusercontent.com 上的同名源文件与相关源码（已逐一打开）。官网的 #seedtoken 锚点表格是由 seeds.ts 的 JSDoc 自动生成的，本报告直接引用了该 JSDoc。若需截图或页面原貌，请在有外网的环境再核对一次。

## recommendations
- 建议：部门规范采用与 antd 5 同构的三层命名，但用自己的中英文名，不要照抄 antd 名字。第一层「基础档位」（对应 Seed）只放：brand #2863CD、sidebar #142F54、workspace #F3F5F9、fontBase 14、spaceUnit 4、radiusBase、lineWidth 1、controlHeight 32，控制在 20 个以内。第二层「用途命名」（对应 Map+Alias）用「用途-层级」写法，例如 color.bg.layout、color.bg.container、color.text.primary、color.text.secondary、space.xs/sm/md/lg/xl = 4/8/12/16/24、font.size.sm/base/lg/xl/h2 = 12/14/16/24/32。第三层「端侧映射」是一张表，把每个用途名映射到三端的真实变量名。
- 建议：把三层写成一个单一源文件（例如 design-tokens.json，放在部门公共仓库），再用一个很小的脚本生成三份产物：Web 端生成 antd ConfigProvider 的 theme.token 对象（key 用 antd 名：colorPrimary、colorBgLayout、colorBgContainer、fontSize、sizeUnit…）或 --ant-* CSS 变量；H5 端生成 :root:root { --adm-color-primary: #2863CD; --adm-color-box: #F3F5F9; --adm-color-background: #fff; --adm-font-size-main: 14px; } 文件；小程序端生成 page { --color-brand1: #2863CD; --color-background: #F3F5F9; --color-card: #fff; --size-font4: 28rpx; } 写进 app.wxss / app.acss。这一步 Ant Design 官方没有提供，需要部门自建，但工作量很小（一个 20 行脚本）。
- 建议：尺寸单位规则写死为「源文件只存 px 逻辑像素；Web 与 H5 直接输出 px；小程序输出时乘 2 变 rpx（14px → 28rpx，4px → 4rpx 例外要标注）」，并在规范里用一句话解释 rpx：屏幕宽恒为 750rpx，375pt 宽手机上 2rpx = 1px。这与 antd-mini 官方「@rpx: 1rpx，组件尺寸写 N * @rpx」的做法一致。
- 建议：H5 端在规范中明确写出 antd-mobile 与本部门的三处默认值差异并声明覆盖：--adm-font-size-main 13px → 改为 14px（满足本部门「正文不小于 14px」原则）；--adm-color-success #00b578、--adm-color-warning #ff8f1f → 若要与 Web 端一致需在 :root:root 覆盖；覆盖必须用 :root:root 选择器（官方要求）。
- 建议：小程序端在规范中标注两个陷阱：1) --color-background 在 antd-mini 里是灰色页面底（#f5f5f5），--color-card 才是白色容器，不要与 H5 的 --adm-color-background（白色）混淆；2) 支付宝小程序页面需把 page.json 的 styleIsolation 设为 shared 才能让页面样式覆盖组件（antd-mini FAQ 官方说明）。微信端引入路径是 antd-mini/ConfigProvider/index，支付宝是 antd-mini/es/ConfigProvider/index。
- 建议：深色模式暂不纳入首版规范，但变量设计要为其留位：三端官方深色方案都是「同名变量换一套值」（antd 用 darkAlgorithm，antd-mobile 用 html[data-prefers-color-scheme='dark']，antd-mini 用 @media (prefers-color-scheme: dark) 或 theme="dark"），所以只要用途命名层做对了，深色只是多一列值。
- 建议：本部门字号档 12/14/16/24/32 中的 32 不在 antd 梯度（antd 是 30/38）里，属于部门自定义档位，规范里要标注「部门规则，非 antd 默认」；间距档 4/8/12/16/24/32 与 antd 的 sizeXXS～sizeXL 完全重合，可直接标「与 antd 一致」。
- 建议：验收方法——写一个「三端变量快照」检查：脚本读取生成出的 antd theme.token、--adm-* 文件、小程序 --color-* 文件，逐条比对源文件，任何一端漏掉或值不等即失败；每次改源文件必须同时提交三份产物，PR 里附三端截图（Web 客户列表页、H5 客户列表页、小程序客户列表页）证明主色与页面底色一致。
