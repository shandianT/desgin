# 查证：「一份变量源 → 多端样式文件」的行业标准链路（DTCG 格式 + Style Dictionary + Figma／Tokens Studio + 版本管理）
行业标准链路是：设计变量（design token，即「颜色、间距、字号这些设计决定」的可机读记录）只写在一份 JSON 源文件里，按 W3C 设计令牌社区组（DTCG）格式表达（每个变量有 $value、$type，可用 {color.blue.600} 引用别的变量）；再用 Style Dictionary 这类「翻译器」按端生成 CSS 变量、小程序 WXSS、iOS Swift、Android XML 等文件，单位换算（如 px→rpx、px→pt）写成一个几行代码的自定义 transform；设计工具侧用 Figma Variables 或 Tokens Studio 插件把同一份 JSON 同步到 Figma；版本用语义化版本号（semver）加人写的更新日志（Keep a Changelog）。本次核实发现：官方站点 tr.designtokens.org、styledictionary.com、docs.tokens.studio、help.figma.com、微信开发者文档均被网络代理拦截，全部结论改为从各项目的官方 GitHub 源码仓库核实（规范正文、文档源文件、代码、OpenAPI 定义），并逐条标明。部门现有 tokens.json 与 build-tokens.mjs 已经走在正确方向上（$value／$type／别名／基础层→语义层→端侧覆盖），但有三处与标准不兼容：dimension 值写成裸数字、platforms 覆盖段不是合法 DTCG 结构、生成脚本是自研而非标准工具，这会影响以后接入 Figma／Tokens Studio 和原生 App。「改一处颜色，三端同步」的关键不在工具，而在两个人工环节：各端组件必须真的引用生成的变量而不是硬编码（小程序 app.wxss 目前仍是硬编码色值），以及每次改值走 PR 评审 + 构建 + 验收。

- **[官方事实] DTCG 格式当前稳定版为 2025.10（2025-10-28 发布），用「年.月」日期做版本号；文件是 JSON，推荐扩展名 .tokens 或 .tokens.json，媒体类型 application/design-tokens+json**
  来源：community-group/README.md 第 94～106 行（版本表）；technical-reports/format/file-format.md 第 3、15、25～26 行
  README 版本表：2025.10 → www.designtokens.org/TR/2025.10/ → Stable；third-editors-draft（2025-07-21）为草案。原文：「tools can use the date as a version number to signify compliance. For example: 2025.10」。file-format.md：「Design token files are JSON files」；MIME「application/design-tokens+json」，也可用 application/json；扩展名「.tokens」「.tokens.json」。示例文件顶部可写 "$schema": "https://www.designtokens.org/schemas/2025.10/format.json"（types.md 第 32 行），仓库 schemas/src/2025.10/format/ 下有 token.json、group.json 等 JSON Schema 源文件。
- **[官方事实] DTCG：带 $value 的对象就是一个变量（token）；$value 必填，$type 可写在变量或其任一父分组上（就近继承），$description、$extensions、$deprecated 可选；名字不能以 $ 开头，且不能含 { } 和 .**
  来源：community-group/technical-reports/format/design-token.md 第 21、33、76～82、86、122～128、157～160、194 行
  原文要点：「An object with a $value property is a token」「Name and value are both required」；$type 缺省时「inherited from the closest parent group with a $type property」，否则「the token MUST be considered invalid」，且「Tools MUST NOT attempt to guess the type」；$extensions 用反域名键，如 "org.example.tool-a"，其他工具「MUST preserve any extension data they do not themselves understand」；$deprecated 可为 true／false／说明字符串。示例：{"Button background":{"$type":"color","$description":"...","$value":{"colorSpace":"srgb","components":[0.467,0.467,0.467]}}}
- **[官方事实] DTCG 别名语法："$value": "{colors.blue}"，大括号里是「分组.变量」点分路径，只能指向完整变量并解析为其 $value；允许链式引用，禁止循环引用；属性级引用需用 JSON Pointer 的 $ref**
  来源：community-group/technical-reports/format/aliases.md 第 18、36、47、51、69～72、88～93、123、156、170 行
  原文：「always resolves to the $value property of the target token」「Curly brace references can ONLY target complete tokens」；对比表：{group.token} ↔ #/group/token/$value。链式：「Aliases MAY reference other aliases…tools MUST follow each reference」；循环：「References MUST NOT be circular…Tools MUST detect and report this as an error」。$ref 示例："primary": {"$ref": "#/colors/blue"}，"primaryHue": {"$value": {"$ref": "#/colors/blue/$value/components/0"}, "$type": "number"}。可直接写进规范：部门 tokens.json 里的 "{color.blue.600}" 写法与规范一致。
- **[官方事实] DTCG 分组：没有 $value 的对象就是分组；分组可带 $description、$type（作为子变量默认类型）、$extends、$deprecated、$extensions；一个对象不能既有 $value 又有子变量；分组本身的值用保留名 $root**
  来源：community-group/technical-reports/format/groups.md 第 3、7～13、19、64～72 行
  原文：「A group is identified as a JSON object that does NOT contain a $value property」「If an object contains both $value and child tokens/groups…Tools MUST report this as an error」「Groups are arbitrary and tools SHOULD NOT use them to infer the type」。类型继承示例："color": {"$type": "color", "primary": {"$value": {...}}}。注意：分组下的普通属性若既不是 $ 前缀也不是含 $value 的对象，就不是合法结构（这影响部门 tokens.json 的 platforms.overrides 段，见仓库证据）。
- **[官方事实] DTCG 2025.10 的 dimension 值必须是对象 {"value": 数字, "unit": "px"|"rem"}，即使为 0 也要写 unit；规范明确 px 对应 Android dp／iOS pt，rem 对应 Android 16sp，翻译工具应做换算**
  来源：community-group/technical-reports/format/types.md 第 17～57 行（Dimension 与 Validation）
  原文：「The value MUST be an object containing a numeric value…and unit of measurement ("px" or "rem")」；示例 "spacing-stack-0": {"$value": {"value": 0, "unit": "px"}, "$type": "dimension"}；「px: Represents an idealized pixel on the viewport. The equivalent in Android is dp and iOS is pt. Translation tools SHOULD therefore convert to these or other equivalent units as needed」「The equivalent of 1rem on Android is 16sp」「$value.unit is still required even if $value.value is 0」。对部门的意义：间距 4/8/12/16/24/32 应写成 {"value": 4, "unit": "px"}（严格 2025.10）或 "4px"（Style Dictionary 兼容写法，见后），不应写裸数字 4。
- **[官方事实] DTCG 2025.10 的 color 值是对象 {colorSpace, components, alpha?, hex?}，hex 只是 6 位回退值；其他类型还有 fontFamily、fontWeight（1～1000 或名字）、duration、cubicBezier、number，以及复合类型 shadow、border、typography、gradient、transition、strokeStyle**
  来源：community-group/technical-reports/color/color-type.md 第 11～16 行；format/types.md 第 59～210 行标题；format/composite-types.md 标题行 135～641
  color-type.md：「colorSpace (required)」「components (required)」「alpha (optional)…If omitted…assumed to be 1」「hex (optional): A string that represents a fallback value…MUST be formatted in 6 digit CSS hex」。示例 {"colorSpace": "srgb", "components": [1, 0, 1], "alpha": 1, "hex": "#ff00ff"}。fontWeight：「a number value in the range [1, 1000] or one of the pre-defined string values」。注意：Style Dictionary 文档承认「the latest format 2025.10 does not have full support yet」，所以 #2863CD 这类字符串色值在工具链里仍是主流写法（见 Style Dictionary 条目）。
- **[官方事实] Style Dictionary（当前 v5.5.4）的构建流程：读 config → 按 source/include 通配找变量文件 → 深合并成一个字典 → 每个 platform 依次跑 transforms（改名字/值/属性）→ 解析 {a.b} 引用 → 用 format 生成 files → 可选 actions**
  来源：style-dictionary/docs/src/content/docs/info/architecture.md；package.json 第 3 行 "version": "5.5.4"；reference/config.md
  architecture.md 原文：「This allows you to split your token files in any way you like」「Value transforms…are skipped if the token references another token」，随后「resolves aliases in the format "{size.font.base}"」。config 字段（config.md）：source（string[]，深合并）、include（默认值，会被 source 覆盖）、platforms.<name>.{transformGroup, transforms, buildPath（须以 / 结尾）, prefix, basePxFontSize, files[{destination, format, filter, options}]}、usesDtcg（自动检测）。最小配置示例（examples/basic/config.json）：{"source": ["tokens/**/*.json"], "platforms": {"css": {"transformGroup": "css", "buildPath": "build/css/", "files": [{"destination": "_variables.css", "format": "css/variables"}]}}}。
- **[官方事实] Style Dictionary 从 v4 起原生支持 DTCG 写法（$value/$type/$description），自动检测 usesDtcg；同一实例内不能混用 $value 与 value 两种写法；v5 起引用只能指向变量本身（不能指向分组或 $value 内部字段）**
  来源：style-dictionary/docs/src/content/docs/info/DTCG.mdx 第 13～16 行；info/tokens.md 第 11～16 行；versions/v5/migration.md 第 13～40 行；lib/common/transforms.js isDimension 等过滤器
  DTCG.mdx：「As of version 4, Style Dictionary has first-class support for the DTCG format」「Important note: the latest format 2025.10 does not have full support yet in Style Dictionary」。tokens.md：「In version 4 you can use either format, pick one though as they cannot be combined inside a single Style Dictionary instance」。v5 migration：「We no longer allow you to create token references to non-token leaf nodes」。代码：function isDimension(token, options) { return (options.usesDtcg ? token.$type : token.type) === 'dimension'; } —— 即所有内置过滤器同时认 $type 和旧 type。官方 basic 示例的 DTCG 写法：{"dimensions": {"$type": "dimension", "1": {"$value": "4px"}, "2": {"$value": "8px"}}}（examples/basic/tokens/dimensions.json）。
- **[官方事实] Style Dictionary 的尺寸 transform 同时接受 "16px" 字符串和 DTCG 的 {value, unit} 对象，因此部门无论用哪种写法都能被内置 size/* 变换处理**
  来源：style-dictionary/lib/common/transforms.js 第 377～415 行 getTokenDimensionValue
  代码注释：「Parse and normalize the value of a dimension Token as DTCG dimension value -> { value: 15, unit: 'em' }」；实现：若值是对象则返回 { value: val.value, unit: val.unit }，否则用正则 /[^0-9.-]+$/ 从 "16px" 里拆出单位。裸数字（如部门现在写的 4）会被当作「unitless dimension」，注释说这是历史遗留、未来可能废弃：「We can deprecated this and remove that in a breaking change」。
- **[官方事实] 自定义单位换算（如 px→rpx）的官方机制：StyleDictionary.registerTransform({ name, type: 'value', filter, transform, transitive? })，再用 registerTransformGroup 或 platform.transforms 挂到某个端；注册必须在创建实例之前**

## recommendations
- （建议）变量源文件改名并标注规范：tokens.json → design.tokens.json，顶部加 "$schema": "https://www.designtokens.org/schemas/2025.10/format.json"，$meta 里 format 字段改为「DTCG 2025.10（Style Dictionary v5 兼容子集）」。
- （建议）dimension 值统一改成带单位字符串 "4px"（Style Dictionary v5 官方 basic 示例写法，getTokenDimensionValue 可解析），并在规范里注明「待 Style Dictionary 完整支持 2025.10 后迁移为 {"value": 4, "unit": "px"}」；不要再写裸数字。
- （建议）platforms 覆盖段改为 Style Dictionary 官方 multi-brand-multi-platform 示例的目录法：tokens/global/*.json 放基础与语义变量；tokens/platforms/web.json、mobile-web.json、miniprogram.json、app.json 只放同名语义变量的覆盖（每个仍是含 $value 的合法变量），构建时按端拼接 source。这样文件既是合法 DTCG，又能被 Tokens Studio 导入。
- （建议）$extensions 的键从 "dept" 改为反域名，如 "cn.sensetime.sales-design"，内容保留 status（已确认／建议）与 rule（V-01 等）；规范里规定这是部门唯一允许的扩展键。
- （建议）用 Style Dictionary v5 替换自研 build-tokens.mjs 的生成部分，保留它的「中文对照表」和 check-tokens.mjs 的一致性校验。最小配置：platforms.web = { transformGroup: 'web', files: [{ destination: 'design-tokens.css', format: 'css/variables' }] }；platforms.miniprogram = { transforms: ['attribute/cti','name/kebab','size/px','color/css'], files: [{ destination: 'design-tokens.wxss', format: 'css/variables', options: { selector: 'page' } }] }；platforms.ios = { transformGroup: 'ios-swift-separate', files: [{ destination: 'DesignTokens.swift', format: 'ios-swift/enum.swift' }] }；platforms.android = { transformGroup: 'android', files: [{ destination: 'design_tokens.xml', format: 'android/resources' }] }。名字前缀用 platform.prefix: 'ui'，即可得到 --ui-primary。
- （建议）单位换算写成自定义 transform 而不是改源值：小程序若需要 rpx，注册 StyleDictionary.registerTransform({ name: 'size/pxToRpx', type: 'value', filter: (t) => t.$type === 'dimension', transform: (t) => `${parseFloat(t.$value) * 2}rpx` })，并只在需要按屏宽缩放的变量上用（用 $extensions 打标或按名字过滤）；iOS/Android 端因为源是 px，不要用会乘 16 的 size/remTo* 变换，改用 size/dp、size/sp 或自定义 px→pt（1:1）。这一条依赖微信 rpx 官方定义，落地前先核实。
- （建议）Figma 侧先不依赖 Enterprise 的 Variables REST API（官方标注仅 Enterprise 可用），用 Tokens Studio 插件（默认 DTCG 格式，可同步到 GitHub）作为设计师改值入口；每个 Figma 变量的 codeSyntax 填三端代码名（WEB: var(--ui-primary)、iOS: DesignTokens.uiPrimary、ANDROID: @color/ui_primary），让设计稿标注直接显示代码名。
- （建议）版本与变更流程写进规范：变量库遵循 semver 2.0.0（删名／改含义 = MAJOR，新增 = MINOR，仅改值 = PATCH）；CHANGELOG.md 遵循 Keep a Changelog（Unreleased 段、六类、YYYY-MM-DD、先 Deprecated 后 Removed、**Breaking:** 标记）；变量废弃用 DTCG 的 "$deprecated": "请改用 {ui.primary}"，至少保留一个 MINOR 版本再删。
- （建议）明确四个必须人工的环节并写成验收清单：① 改值 PR 需设计与前端各一人评审；② 各端「无硬编码色值／尺寸」检查（可用 grep 规则：禁止 #[0-9a-f]{3,8} 与非 var() 的 px 出现在组件样式里）；③ 生成产物与 1.0.0 快照的 check 脚本必须通过；④ 三端截图对照签字后才打 tag。小程序当前 app.wxss 全是硬编码，应作为第一个接入试点。
- （建议）把本报告里「官方事实」条目整理成规范附录「术语与依据」，每条附 GitHub 源码路径与提交号；待网络放开后再补官方网页链接并复核 2025.10 网页版与源码是否一致。
