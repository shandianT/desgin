# 微信小程序官方硬性事实查证：rpx／样式变量／页面栈／tabBar／安全区／键盘（供部门设计规范跨端章节引用）
本次查证的目标是弄清「Web 的 px 变量搬到微信小程序要怎么处理」以及「返回、Tab、安全区、键盘哪些是平台自带、规范只需引用」。重要说明：本会话的网络代理直接拦截了 developers.weixin.qq.com（含 /miniprogram/design/）以及 CSDN、博客园、腾讯云等国内站点，所以没有一条结论来自「实际打开的官方页面」；凡涉及官方文档原文的条目一律标为「未能核实」，并注明我实际打开的替代来源（GitHub 上的官方文档镜像、uni-app／Taro／mpx 等框架文档中逐字转录的微信原文）。真正打开并读到的「官方」材料只有腾讯／微信官方在 GitHub 上的 WeUI 源码与 README（Tencent/weui-wxss、wechat-miniprogram/weui-miniprogram），这些条目标为「官方事实」。核心结论：（1）小程序把屏幕宽定为 750rpx，iPhone6 上 1rpx＝0.5px；颜色、字号、圆角、控件高度这类「不随屏宽缩放」的变量可以原样用 px，页面左右留白、栅格这类「随屏宽缩放」的量才用 rpx；（2）微信官方 WeUI 就是用 `page{--weui-…}` 定义 CSS 变量再 `var()` 引用，单位用 px，并另给 rpx 版本，说明本仓库 dist/design-tokens.wxss 采用 `page{--ui-…: px}` 的写法与官方实践一致；（3）navigateTo→navigateBack 时前一页只触发 onHide／onShow、不卸载，页面栈上限 10 层，switchTab 会卸载所有非 Tab 页——「返回保留列表状态」是平台自带能力，规范只需规定「onShow 里不要粗暴重置筛选与滚动」；（4）系统导航栏、tabBar（2～5 个、图标 81×81px≤40KB）、启动页、下拉刷新、键盘上推（adjust-position 默认 true）都是平台自带，规范只需引用并给出品牌色与安全区写法；（5）仓库现状：客户列表页把详情做成页面内 fixed 浮层并自画返回键，绕开了系统返回，这与「客户列表→详情→返回」跨端样板的目标冲突，是最值得先修的一处。

- **[未能核实] 路由与生命周期对照（官方表）：navigateTo → 前页 onHide、新页 onLoad+onShow；navigateBack（含左上角返回按钮）→ 当前页 onUnload、目标页 onShow；redirectTo → 当前页 onUnload；switchTab → 从 Tab 页 A 到 B 首次「A.onHide(), B.onLoad(), B.onShow()」，再次「A.onHide(), B.onShow()」，从非 Tab 页 C 切换则「C.onUnload()」；reLaunch → 当前页 onUnload。**
  来源：官方页 https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/route.html（未能打开）。镜像：https://raw.githubusercontent.com/wepyjs/weapp-document-tracker/master/md/_debug_wxadoc_dev_framework_app-service_route.md（已打开读取，含页面栈行为表与 Tips）。
  镜像原文（页面返回行）：「调用 API wx.navigateBack 或使用组件或用户按左上角返回按钮」→ 路由前页面 onUnload，路由后页面 onShow。Tips：「navigateTo, redirectTo 只能打开非 tabBar 页面。switchTab 只能打开 tabBar 页面。reLaunch 可以打开任意页面。」「不要尝试修改页面栈，会导致路由以及页面状态错误」。uni-app 文档转录的 onHide／onUnload 定义：「页面隐藏/切入后台时触发。如 navigateTo 或底部 tab 切换到其他页面，小程序切入后台等。」「页面卸载时触发。如 redirectTo 或 navigateBack 到其他页面时。」（来源 dcloudio/uni-app docs/page.md，GitHub 代码搜索命中）。
- **[推论] 由上表可推出：navigateTo 打开详情、navigateBack 返回时，列表页从未被卸载，其 data、DOM 和滚动位置由平台原样保留，只会再执行一次 onShow；因此「返回保留筛选与位置」在小程序上是平台自带，规范只需约束 onShow 不要清空状态。**
  来源：推论依据：上一条镜像生命周期表（navigateTo 只触发 onHide，不触发 onUnload）。

## recommendations
- （建议）在规范第 06 章「单位适配」写死一条判定规则：不随屏宽缩放的变量（颜色、字号、圆角、边线、控件高、阴影、44px 触控目标）在小程序输出 px；只有页面留白、列宽、栅格允许用 rpx，且必须在变量对照表标注「rpx／750 基准」；1px 细线禁止用 rpx。依据是官方毛刺提示与官方 WeUI 默认 px 的做法。
- （建议）把 dist/design-tokens.wxss 复制到 frontend/miniprogram/ 并在 app.wxss 第一行 `@import "./design-tokens.wxss";`，然后先只改客户列表／客户详情两页，把裸色值与 rpx 字号替换为 var(--ui-…)；这是「客户列表→详情→返回」样板最小的接入动作，也能验证 page{--x} + var() 在真机的可用性。
- （建议）app.json 里原生 tabBar 与 window 的颜色无法引用 CSS 变量，建议让 build-tokens.mjs 额外生成一份 app.tokens.json 片段（tabBar.color/selectedColor/backgroundColor、window.navigationBarBackgroundColor/backgroundColor），并在 check-tokens.mjs 中比对 app.json 是否一致；当前 selectedColor #1677FF 与主色 #2863CD 不一致应作为第一条变更单。
- （建议）跨端样板「客户列表→详情→返回」在小程序上应改为 wx.navigateTo 打开 pages/customer-detail，废弃 customers 页内的 detail-overlay 浮层与 pendingOpenCustomerId 存储机制，让系统返回、右滑返回、导航栏标题全部由平台接管；验收项写为：Android 硬件返回、iOS 右滑、导航栏返回三种方式结果一致，且列表筛选与滚动位置保留。
- （建议）规范中「返回保留状态」在小程序端的实现规则只需一句：列表页 onShow 只做增量刷新，不得重置筛选、选中项与滚动位置；并注明 switchTab 与 reLaunch 会清空页面栈，属于允许的例外（X-12 登记）。
- （建议）底部固定操作条统一写法：`padding-bottom: calc(<自身间距> + constant(safe-area-inset-bottom)); padding-bottom: calc(<自身间距> + env(safe-area-inset-bottom));`（两行，env 在后），来源为官方 WeUI；自定义导航栏高度不写死，按 wx.getMenuButtonBoundingClientRect 计算。
- （建议）键盘：规范只写三条——输入框保持 adjust-position 默认 true；固定在底部的输入条设置 cursor-spacing（本仓库已用 24）；放在 position:fixed 浮层内的 textarea 必须加 fixed="true"。其余交由平台。
- （建议）字号对照表加一列「微信官方常用档」：20/18/17/16/14/13/11pt，并注明小程序 1px＝1pt；部门手机正文 16px 落在官方 14～17 之间可保留，说明文字 12px 低于官方最小 11pt 之上 1 档、可保留。
- （建议）由能访问官网的同事按各条 finding 列出的官方 URL 复核一次并在来源清单登记复核日期；所有标「未能核实」的条目在复核前只能写进规范的「待核实」栏，不作为已确认规则。
