# 腾讯 TDesign 生态与微信 WeUI 小程序版查证：小程序端首选 tdesign-miniprogram

> 查证日期 2026-09-19。官网（semi.design、tdesign.tencent.com、weui.io、vant、ant.design、arco.design、webawesome.com 等）与 GitHub 网页／API 在本会话均被代理拦截；本文全部事实来自 raw.githubusercontent.com 的官方仓库源文件、registry.npmjs.org 元数据与实际下载的 npm 发布包。「官方事实」= 官方仓库文档或元数据原文；「仓库证据」= 读源码得到；「推论」= 由前两者推出；「未能核实」= 只在官网或不可达资源上有。由 AI 查证，待有网络的同事按来源复核。

查证结论：结论：小程序端首选 tdesign-miniprogram（1.16.1，2026-09-09 发版，MIT，102 个组件目录，七类组件全覆盖），WeUI 小程序版只作「微信原生视觉」的补位备选。理由有三：（1）TDesign 是本轮查到的唯一同一套 Design Token（设计变量：把「主色 = #2863CD」这类设计决定起名集中维护）命名 --td-* 同时覆盖 Web React/Vue、移动 H5、微信小程序的官方体系，核心变量 179 个三端同名，只是小程序里的字号、圆角、间距用 rpx（小程序按屏宽等比缩放的单位）而 Web 用 px；（2）主题覆盖方式极简：官方文档写明在 app.wxss 里 `page { --td-brand-color: … }` 即可换主色，组件级变量同法；（3）维护活跃：近 12 个月发版 24 次，仓库最后推送 2026-09-18。WeUI 小程序版 npm 最后发版 2024-11-15，近 12 个月 0 次发版，只有 20 个组件，没有 picker、表格、筛选栏、toast、骨架屏，主色是微信绿 --weui-BRAND-100:#07c160，且文档没有「自定义主题」章节，不适合作主库。tdesign-web-components 于 2026-09-03 刚拆包为 @tdesign/web-components 1.3.2（提供 UMD 单文件，可在无框架 HTML 里用 `<script src="https://unpkg.com/@tdesign/web-components@<version>/dist/web-components.min.js">`），但仓库在 TDesignOteam 组织、37 star、46 个组件、没有 Table/Form/Cascader/Drawer，定位桌面端，只能算「可用但不成熟」，不建议作为 sales-web 主库。主题变量映射落点：在部门规范仓库 /home/user/desgin/specs/salesbuddy/02-设计变量与同步链路/build-tokens.mjs 增加第六个产物 dist/tdesign-bridge.wxss（以及 Web 用的 dist/tdesign-bridge.css），内容是 `page { --td-brand-color: var(--ui-primary); … }` 这类「--td-* 指向 --ui-*」的桥接；产品仓库 /home/user/xiaoshouguanli/frontend/miniprogram/app.wxss 头两行 `@import "./design-tokens.wxss"; @import "./tdesign-bridge.wxss";`，并按官方要求删除 app.json 第 51 行的 "style": "v2"。网络限制：tdesign.tencent.com、weui.io、developers.weixin.qq.com、GitHub 网页与 REST API、api.npmjs.org 全部被代理拦截；本轮全部事实来自 raw.githubusercontent.com、npm registry 元数据与 tarball、以及 git clone 的官方仓库源码（官网页面本身就是从这些 site/docs/*.md 生成的），官网原文与 npm 下载量标「未能核实」。

## recommendations

- 小程序端首选 tdesign-miniprogram 1.16.1，不选 WeUI 作主库：TDesign 是查到的唯一与 Web／H5 共用 --td-* 变量命名的官方小程序库，七类组件全覆盖，MIT，月度发版；WeUI 小程序版近 12 个月未发版、只有 20 个组件、缺选择器／表格／筛选栏／toast，主色为微信绿且无主题文档。WeUI 只在需要「与微信原生一模一样」的少数场景（navigation-bar、half-screen-dialog）作为补位，且两库不要在同一页面混用。
- 主题变量落点：在 /home/user/desgin/specs/salesbuddy/02-设计变量与同步链路/build-tokens.mjs 增加第六、七份产物 dist/tdesign-bridge.wxss（page 选择器）与 dist/tdesign-bridge.css（:root 选择器），内容为 --td-brand-color: var(--ui-primary) 等约 20 条「TDesign 变量指向部门 --ui-* 变量」的映射（清单见 finding「主题变量映射的落点」）；check-tokens.mjs 新增校验：桥接文件里的每个 --td-* 名字必须存在于当前锁定版本的 tdesign-miniprogram/miniprogram_dist/common/style/theme/*.wxss。
- 产品仓库接入四步（由小程序开发执行并在采用登记表登记版本 1.16.1）：① frontend/miniprogram 下 npm init 并 npm i tdesign-miniprogram -S --production，开发者工具「构建 npm」并勾选「将 JS 编译成 ES5」；② 删除 app.json 第 51 行 "style": "v2"，随后回归检查原生 button/input 外观；③ app.wxss 头两行 @import "./design-tokens.wxss"; @import "./tdesign-bridge.wxss";，页面按 usingComponents 引入 t-button 等；④ 小程序后台最低基础库设为 2.12.0 以上（建议 3.x），并按官方要求填写用户隐私保护指引（Upload 用 wx.chooseMedia）。
- 品牌色十档：部门 tokens.json 目前只有 blue 50/400/600/700 四档，TDesign 依赖 --td-brand-color-1～10。请有网络的同事用官网主题生成器（或 npm 包 @tdesign/theme-generator 1.2.7）以 #2863CD 生成十档，写回 tokens.json 的 color.blue 基础层，由 build 输出到桥接文件；在此之前未映射档位落 TDesign 默认值。
- Web（sales-web）不要把 @tdesign/web-components 当整站底座：它刚拆包、37 star、缺 Table/Form/Cascader/Drawer、定位桌面端。短期：保留 tom-select、flatpickr、echarts，但把它们的配色改为读 dist/design-tokens.css 的 --ui-*；可用 UMD 单文件局部替换按钮、输入、Select、Dialog、Message。中期：若 sales-web 引入 React 或 Vue3，直接用 tdesign-react 1.18.3 或 tdesign-vue-next 1.20.8，同一份 dist/tdesign-bridge.css 生效，无需重做主题。
- 移动 H5 如需要：优先 tdesign-mobile-vue 1.16.2（组件与小程序同名，1.x 稳定）；tdesign-mobile-react 仍是 0.23.3／1.0.0-beta，暂不作为首选。
- 待核实与验证清单（登记到 采用登记表.md 的待决定事项）：① 官网 custom-theme／getting-started 页面原文与仓库 site/docs 是否一致；② npm 月下载量；③ 真机验证 app.wxss 的 page{--td-brand-color} 覆盖生效，以及 app.json 未开 darkmode 时 prefers-color-scheme:dark 分支不触发；④ 字号／圆角／间距变量传给 TDesign 时用 px 还是换算成 rpx（建议按 X-09 用 px），真机看 28rpx 与 14px 是否一致；⑤ tdesign-miniprogram README 的最低基础库 ^2.6.5 与文档 ^2.12.0 不一致，以 2.12.0 为准。
