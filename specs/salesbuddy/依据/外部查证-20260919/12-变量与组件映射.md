## 理由与边界

名词一句话：Design Token（设计变量）＝把「主色 = #2863CD」这类决定起名集中维护；CSS 变量＝浏览器原生 --名字: 值，运行时可覆盖、不用编译；Sass 变量＝构建期编译进 CSS 后就固定的变量；rpx＝小程序按屏宽等比缩放的单位，750 设计稿下 2rpx≈1px；岛屿式挂载＝在现有页面某个容器里单独启动 React 渲染一块组件，其余页面不动。

一、为什么是 Semi＋TDesign 而不是一家通吃。用户点名「飞书的成熟组件」，开源世界里飞书血统只有 Semi Design，但 Semi 只有 React、无小程序版；小程序端必须另选，而 tdesign-miniprogram 是唯一变量名与 Web 版同名（--td-*）、且月度发版的大厂小程序库。因此「部门自己的一套」不是一个新组件库，而是：tokens.json（唯一来源，52 个 --ui-* 语义变量）→ 三份桥接产物（ui-to-semi.css、tdesign-bridge.wxss、tdesign-bridge.css）＋七类组件的「选用清单」（每条规则对应哪个上游组件、哪些 prop、哪些变量），组件本体全部来自上游，最多做主题变量覆盖与少量包装。

二、变量映射的可行边界（按源码核实）。Semi 的运行时 CSS 变量只有颜色、圆角、阴影、遮罩（packages/semi-theme-default/scss/global.scss）；字号（$font-size-regular 14px）、控件高（$height-control-default 32px、large 40px）、间距（$spacing-base 16px）、字体族只在 variables.scss 里是 Sass 变量，dist/css/semi.min.css 中不存在 --semi-font-size-*／--semi-height-control-*／--semi-spacing-*（已 grep 核实为 0 处）。所以 --ui-text-*／--ui-space-*／--ui-control-height／--ui-font 在 Semi 侧「无对应」，要么接受 Semi 默认（控件 32／40，用 size="large" 得 40），要么走 semi-vite-plugin／semi-webpack-plugin 在构建期覆盖 Sass 变量（不改源码）。Semi 主色：--semi-color-primary 定义为 rgba(var(--semi-blue-5),1)，而 primary-light-default、focus-border、link 等分别引用 --semi-blue-0/5/6/7，因此正确做法是覆盖原始色盘 --semi-blue-0～9 十个 RGB 三元组（浅色在 body、.semi-always-light，深色在 body[theme-mode="dark"]），而不是只改 --semi-color-primary。TDesign 小程序端：--td-brand-color 经 --td-primary-color-7 指向 --td-brand-color-7，而 light／focus／disabled／active 分别派生自第 1／1／3／8 档（miniprogram_dist/common/style/theme/_light.wxss），所以除 --td-brand-color 外还要给出 --td-brand-color-1～10 十档；字号与圆角变量默认是 rpx（_font.wxss、_radius.wxss），我们的 tokens 是 px，桥接时按 X-09 直接写 px 即可，真机需核对 28rpx 与 14px 是否一致。

三、组件映射结论。七类在两库都有对应；真正的缺口不在组件而在「组合与文案」：C-04 筛选栏两库都没有现成的复合组件，需要一个用上游 Tag／Dropdown 拼装的薄包装；C-01「禁用说明原因」、C-06「异常可重试且不丢筛选」、C-07「次要详情就地展开」都是包装层与业务层的责任。硬缺口只有三处：Semi 侧控件高度 36 与默认 32 不一致（构建期覆盖或接受默认）；小程序 t-picker 无搜索（长列表改 t-cascader filterable 或 t-search＋列表）；小程序 t-table 在微信端无作用域插槽，单元格只能是文本，手机列表按 C-05 用 t-cell 即可，不冲突。

四、证据边界。semi.design、tdesign.tencent.com、unpkg、jsdelivr、GitHub 网页与 API 均被代理拦截；本文全部依据本地克隆 /home/user/douyinfe/semi-design（commit 82c5389c19730df4b6097842a61927596922f529，2026-09-17，semi-ui 2.103.0）、tdesign-miniprogram 1.16.1 npm tarball 与官方仓库 packages/tdesign-miniprogram/site/docs/*.md（官网页面即由此生成）、以及产品仓库 /home/user/xiaoshouguanli/frontend/miniprogram/app.json:51-52（"style":"v2"、"lazyCodeLoading":"requiredComponents"，无 package.json，project.config.json:48 libVersion 3.17.2）。凡只有官网或真机才能确认的条目在 open_questions 标「待核实」。
