# 小程序样式与「客户列表→详情→返回」现状核查

> 目的：把「跨端建议」对照真实小程序代码，看差距在哪。以下全部是本仓库代码里读到的事实，附文件位置；判断另标「推论」。微信官方文档在本环境被网络策略拦截，涉及平台行为的判断均为推论，待有网络的同事复核。

## 1｜数字先看

rpx 是小程序的等比单位，375px 宽的手机上 2rpx = 1px，所以 28rpx 就是正文底线 14px、24rpx 是说明底线 12px。统计范围：`frontend/miniprogram` 下 24 个 wxss（含 app.wxss 与 battle-map.wxss）。

| 项 | 数值 | 位置 |
|---|---|---|
| wxss 文件数 | 24 | `frontend/miniprogram/**/*.wxss` |
| `var(--` 使用次数 | **0** | 全部 wxss |
| `rpx` 出现次数 | 4630 | 全部 wxss |
| `font-size` 声明 | 914 条 | 全部 wxss |
| 其中 <24rpx（375 宽屏下 <12px） | **717 条（78%）** | 最小 10rpx≈5px |
| 其中 <28rpx（<14px） | 808 条（88%） | 页面根字号 28rpx=14px |
| Web 六个规则色值命中 | **0 处** | #2863CD／#142F54／#F3F5F9／#27694C／#805919／#A73F38 |
| 主色 #1677FF 命中 | 样式文件（wxss）6 个 23 处；含 js／json 全仓 16 个文件 42 处；另有 4 个 tabBar 图标 svg 也用此色 | 另有十余种蓝色渐变 |
| 客户页独立色值 | 145 个 | `pages/customers/index.wxss` |

规范要求正文 ≥14px、说明 ≥12px（CLAUDE.md 第 7 条，V-02）。小程序 rpx 对应：正文 ≥28rpx、说明 ≥24rpx。当前 88% 的声明不达标。

## 3｜「客户列表 → 详情 → 返回」的真实路径

小程序里「客户详情」有**三种**呈现：

| 入口 | 实现 | 位置 | 返回怎么做 |
|---|---|---|---|
| 客户卡片点击 | 列表页内 `position:fixed` 全屏浮层（`selectedCustomer`），隐藏 tabBar | `pages/customers/index.wxml:48,90-165`；`index.js:383-402` | 自绘「‹」按钮 `closeCustomer` |
| 作战地图圆点 | 底部「作战卡」抽屉（`selectedBattleCustomer`） | `index.wxml:24,56-88`；`index.js:357-381` | 点遮罩关闭；「查看完整客户」切到浮层 |
| 独立页 `pages/customer-detail` | 已在 app.json 注册，**全仓库无任何 navigateTo 指向它** | `app.json:12`；`pages/customer-detail/index.js` | 系统返回（但没人能进来） |

**返回时状态保留：** 浮层关闭只清空一个字段，keyword、activeFilter、地图筛选、滚动位置都保留（`index.js:399-402`）。这一点符合 X-03。

**但有四个问题：**

1. **系统返回关不掉浮层**（推论）：浮层不进页面栈，Android 物理返回、iOS 右滑、导航栏返回都不会关闭它；原生导航栏标题「作战地图」还叠在自绘标题栏上。X-03 要求「导航栏与系统返回的结果一致」，现状不满足。
2. **跨页面打开客户靠 storage 中转**：工作台、商机列表、智助页等都 `wx.setStorageSync("pendingOpenCustomerId")` 后 `switchTab` 回列表，由列表 onShow 消费（`index.js:343-356`）。加载失败不清键、换账号仍残留、地址不含客户标识，不可分享不可追溯。
3. **失败路径把 tabBar 永久藏起来**：作战卡「查看完整客户」关抽屉时不恢复 tabBar，随后详情加载失败只 toast（`index.js:376-381,395-397`）。
4. **三种详情的页签和操作不一致**：浮层 4 页签有编辑入口无语音按钮；独立页 3 页签有语音按钮无编辑入口。

## 5｜业务口径的偏差（顺带发现，需产品确认）

- 商机阶段与概率：代码 6 阶段 identified 10／qualified 30／solution 50／proposal 70／negotiation 90／won 100，页面 stages 数组是 5 阶段且无「报价推进」；项目口径是 10/30/50/70/90 ↔ 识别／验证／方案／谈判／签约（`utils/customerDetail.js:10-26`）。
- 作战卡把主商机的赢单概率当作客户级分数展示，多商机客户被单一商机代表（`customerDetail.js:159-180`）。
- 列表负责人显示人名 owner_name，不是地盘 ID（`customerDetail.js:133-154`）。
- 「代办事项」应为「待办事项」（`index.js:158`、`index.wxml:140`）。

## 6｜建议的最小接入动作（样板范围内，未执行）

1. `app.wxss` 第一行 `@import "./design-tokens.wxss";`，只改 `customers/index.wxss`、`battle-map.wxss`、`customer-detail/index.wxss` 三个文件：裸色值→`var(--ui-…)`，字号提到 ≥24rpx／28rpx 或直接用 px 变量。
2. 客户卡片改为 `wx.navigateTo('/pages/customer-detail/index?id=…')`，让系统返回、右滑、导航栏返回由平台接管；作战卡保留为「预览」，其「查看完整客户」也 navigateTo。
3. 废弃 `pendingOpenCustomerId` 三个 storage 键；短期保留则在失败与 onHide 时清键。
4. 把 `dist/miniprogram-app.tokens.json` 的五个颜色写入 `app.json`（主色已决定沿用 #2863CD）。
5. 加一条 CI 检查：wxss 里 `font-size` <24rpx 即失败。
