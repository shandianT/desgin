# 文案规范：界面上的每一句话怎么写

销售在小程序和网页里看到的每一个词都是文案：按钮、标题、空态、报错、提示、时间、数字。现在 26 页各写各的：按钮有 40 多种叫法，出错一律「请……」，时间只有「刚刚」。这份规范定一个说法，以后按它写，AI 写页面时也照它查。

## 1｜四条总则

1. **说事，不说情绪。** 写发生了什么、能做什么。不用感叹号，不用「哦」「呢」「亲」，不用「成功！」「抱歉！」。
2. **动词加对象。** 按钮和链接写清做什么、对什么做：「记录拜访」「创建任务」，不写「确定」「提交」「操作」。
3. **先说结果，再说原因，最后说下一步。** 报错和空态都按这个顺序，三句以内。
4. **一个东西一个名字。** 业务词按第 5 节的词表，全产品统一，不用同义词换着说。

## 2｜按钮与链接

| 场景 | 写法 | 例 | 不这样写 |
|---|---|---|---|
| 主操作 | 动词加对象，2～4 个字 | 记录拜访、创建任务、归档 | 确定、提交、OK |
| 次操作 | 动词，可省对象 | 存草稿、取消、返回 | 放弃、算了 |
| 危险操作 | 写清动作，按钮上不写「确定」 | 删除、作废、解除风险 | 确定、是 |
| 处理中 | 动词加「中…」 | 归档中…、保存中… | 请稍候、Loading |
| 禁用 | 按钮文字不变，旁边写原因 | 归档（还有 3 项必填未确认） | 灰掉不说话 |
| 加载更多 | 固定「加载更多」，到底写「已显示全部 N 条」 | | 没有更多了、到底啦 |
| 重试 | 固定「重试」 | | 重新加载、刷新、再试一次 |
| 确认弹窗 | 标题说后果，按钮重复动作 | 标题「删除这条拜访记录？」说明「删除后不能恢复」按钮「删除」「取消」 | 「确定要删除吗？」「是」「否」 |

现在产品里「重新加载」「刷新名单」「重试」三个词是一件事，统一为「重试」。「确认选择」「确认登记」「确认完成」「确认转交」去掉「确认」二字，写「选择」「登记」「完成」「转交」。

## 3｜五种状态的文案

每个列表、每张卡片都有五种情况，每种一个固定句式。对象名换成当前对象。

| 状态 | 句式 | 客户列表的例子 |
|---|---|---|
| 加载中 | 「正在加载对象…」 | 正在加载客户… |
| 空，没条件 | 一句说没有什么，一句说怎么开始 | 还没有客户。点右下角「创建客户」添加第一个。 |
| 空，有筛选 | 「没有匹配的对象。」加「清除条件」按钮 | 没有匹配的客户。 |
| 失败 | 一句原因，一句下一步，加「重试」 | 加载失败，网络不通。检查网络后点重试，筛选条件会保留。 |
| 无权限 | 说没权限，不说对象是什么 | 这条记录不在你的授权范围内。需要查看请联系主管。 |
| 部分缺失 | 显示已有的，说明缺什么 | 已显示 24 家，其中 3 家的潜力还没登记。 |

各对象的空态第一句：客户「还没有客户」、商机「这个客户还没有商机」、拜访「还没有拜访记录」、任务「没有待处理的任务」、风险「没有需要关注的风险」、总结「这周还没有可总结的动作」。

## 4｜报错与提示

- 原因用人话，不出现错误码、接口名、英文。「网络不通」不写「request failed 500」。
- 每条报错带下一步。能重试给重试，要填的说填什么，要找人的说找谁。
- 表单校验写在字段下面，句式「要……」或「……不能为空」：「下一步要写明时间和目标」「客户名称不能为空」。不写「请输入」「格式错误」。
- 成功提示只在用户看不到结果时才弹：「已归档」「草稿已保存」。页面上已经能看到变化的，不弹。
- 提示语不用「请」开头。「请先选择客户」改「先选一个客户」；「请填写驳回原因」改「驳回要写原因」。
- 权限类提示不猜原因：「不在你的授权范围内」，不写「你没有权限」。

## 5｜业务词表

全产品统一叫法。左边是唯一写法，右边是禁用的说法。

| 用 | 不用 |
|---|---|
| 客户 | 用户、企业、公司（指客户时） |
| 商机 | 项目、订单、机会 |
| 拜访 | 跟进、走访、沟通记录 |
| 拜访记录 | 跟进记录、日志 |
| 任务 | 待办、工单 |
| 风险 | 预警、告警、异常（指客户风险时） |
| 关系等级 | 关系分、亲密度 |
| 潜力 | 价值、规模 |
| 主攻区、客户资产、见单打单、客户资源 | 第一象限、Q1、A 类客户 |
| 需关注、向好、转差、待评估 | 黄灯、绿灯、红灯、灰灯（对用户说时） |
| 负责人、地盘 | 归属人、owner |
| 主管、总经理、董事长 | 领导、上级、管理员 |
| 即时总结 | 日报、周报（周报只指导出模板） |
| 归档 | 提交、上报、入库 |
| 草稿 | 暂存、临时 |
| AI 生成、由 AI 起草 | 智能推荐、系统建议、自动生成 |
| 依据 | 来源、证据、参考 |
| 未登记 | 暂无、无、空、— |
| 赢单概率 | 成功率、把握 |
| 毛利 | 利润、盈利 |
| 确收 | 收入确认 |
| 回款 | 收款、到账 |

## 6｜数字、金额、时间

| 项 | 写法 | 例 |
|---|---|---|
| 金额 | 带单位，万元为主，整数不带小数；千万以上用「万」不用「亿」 | 320 万、1,200 万 |
| 缺失 | 「未登记」。0 只在明确是零的时候显示 | 回款：未登记 |
| 百分比 | 整数，带 % | 赢单概率 70% |
| 数量 | 带量词 | 24 家客户、3 条商机、5 个任务 |
| 关系等级 | 「N/10」 | 关系 8/10 |
| 相对时间 | 1 小时内「N 分钟前」，24 小时内「N 小时前」，7 天内「N 天前」 | 2 天前跟进 |
| 绝对时间 | 7 天以上写月日，跨年带年份，需要时刻写 24 小时制 | 9 月 18 日、2025 年 12 月 3 日、9 月 18 日 14:30 |
| 相对时间可查 | 相对时间旁能看到完整日期 | 2 天前（9 月 18 日） |
| 周期 | 「第三季度」「9 月」「本周」 | 不写 Q3、2026-09 |
| 数字与文字 | 数字和单位、中英文之间空一格 | 320 万、Ant Design 6 |

## 7｜标题与范围

- 页面标题是对象名：客户、商机、任务、作战地图、即时总结。不加「管理」「列表」「中心」。
- 标题旁写范围：「客户 · 本人负责 · 24 家」「作战地图 · 华南团队」。范围词用「本人负责」「直属团队」「授权部门」「核心客户」，和权限四级对应。
- 分区标题是名词短语：「待办」「业务动态」「关注与依据」。

## 8｜AI 相关

- 标识固定两种：生成中「AI 生成中…」，待确认「AI 生成，待确认」，已确认「由 AI 起草，某某确认」。
- AI 没把握时写「AI 不确定，请核对」，给候选，不写「可能是」「大概」。
- 依据句式「依据：」加来源名称，可点开：「依据：9 月 12 日拜访记录」。
- 不用「智能」「聪明」「懂你」这类词，不给 AI 起人名，不用「我」自称。

## 9｜标点与格式

- 中文全角标点。句末用句号，列表项末尾不加标点。
- 引用界面上的词用「」，不用双引号。
- 省略号用「…」一个字符。
- 不用括号解释，要解释就另起一句。
- 英文和数字用半角，前后空一格。

## 10｜怎么检查

- 按钮文字是否动词加对象；有没有「确定」「提交」「OK」。
- 空态、失败、无权限三种文案是否按第 3 节句式。
- 有没有「请」开头的提示、感叹号、错误码。
- 业务词是否在第 5 节的「用」列。
- 时间和金额是否按第 6 节。

## 11｜还没定的

- 「即时总结」对用户是否改叫「今日总结」，看神码习惯。
- 主管视角的「团队」是否要区分「直属团队」和「授权部门」两个词，还是统一叫「团队」。
- 英文缩写 ACV 对用户显示「年度合同额」还是保留 ACV，看神码内部叫法。
