# 本轮工作说明：目标、基础与缺口、第一步、需要你决定的事

## 1｜我理解的目标

建立一套**部门自己的、中文的**产品设计规范，让产品、设计、开发、测试和 AI 用同一套规则做事。它要覆盖设计原则、视觉基础（颜色、字体、间距）、组件、页面布局、交互状态、跨端适配（电脑网页、手机网页、微信小程序，可能还有原生 App），以及团队怎么使用、修改、验收和维护。SalesBuddy 销售管理是第一个落地对象，但规范要能服务部门多个产品。学飞书等成熟产品的**方法**，保留自己的业务和品牌。

你最关心的四件事，本轮分别用一份文档回答：哪些统一哪些适配（01）、变量怎么集中维护并同步（02）、三段布局到手机怎么组织（03）、团队怎么协作和维护版本（04）。

## 3｜关键缺口（本轮核查后的判断）

1. **变量没有真正同步到任何端。** 小程序 24 个样式文件里 CSS 变量使用为 0，主色是 #1677FF 不是 #2863CD，88% 的字号声明小于 14px。Web 工程不可见，无法核查。
2. **「返回」在小程序上不是页面级返回。** 客户详情是页内浮层，系统返回、右滑、导航栏返回都关不掉；独立详情页已注册但无人跳转。跨页面打开客户靠 storage 中转。
3. **跨端规则没有样板证据。** X 章 12 条都是文字建议。
4. **没有一条「改一处 → 各端同步」的链路**，也没有版本、变更、采用登记的实际载体。
5. **三处事实冲突：** 主色（需你决定，见第 6 节）、一级导航命名（Web 六项 vs 小程序五 Tab）与客户详情有三种呈现（需产品拍板，见采用登记表）。

## 4｜最值得先做的一步：「客户列表 → 详情 → 返回」跨端样板，评估结论：合适

**为什么合适：** 它同时检验三段布局、移动适配、间距语义、状态保留、共同业务字段、状态覆盖和权限提示，而且是销售每天最高频的动作。它不涉及 AI 归档和写操作，风险最低。

## 8｜名词表（第一次读到时看这里）

| 词 | 一句话 |
|---|---|
| 逻辑像素 | 手机上的 1px 不是一个物理点；375 宽的 iPhone 屏幕就是 375px 逻辑像素。Android 叫 dp，iOS 叫 pt |
| rpx | 小程序把屏幕宽定为 750 份的等比单位；375 宽手机上 2rpx = 1px |
| CSS 变量 | 样式里可以起名字重复引用的值，例如 `--ui-primary` |
| WXSS | 小程序的样式文件，相当于网页的 CSS |
| app.json | 小程序的全局配置文件，底部导航颜色写在这里 |
| storage | 小程序本机的临时存储 |
| navigateTo | 小程序「打开新页面并进入页面栈」的接口；返回时前一页还在 |
| 设计变量（Design Token） | 把颜色、间距等设计决定起名字集中维护的做法 |
| Style Dictionary | 把变量文件翻译成各端代码的开源工具 |
| 媒体查询 | CSS 按窗口宽度换样式 |
| 容器查询 | CSS 按所在那一栏自身的宽度换样式；例：1024 宽时窗口够宽但详情栏只有 444px，就不分栏 |
| sessionStorage、URL hash | 浏览器的临时存储（关标签页即清）；地址栏 # 后面的参数 |
| Playwright | 自动操控浏览器做检查的工具 |
| PR | 把改动提交给别人审的一张单子（合并请求） |
| tag | 给某一版打的标签，相当于发行号 |
| Compact／Medium／Expanded | Google 对窗口宽度三档的叫法，对应我们的 ≤600／601～900／>900 |
