# 组件生态选型：挑成熟的大厂组件，只做主题微调，形成部门自己可直接调用的一套

> 回答的问题：不自己造组件，用哪家的？怎么只改颜色字号就变成「我们的」？以后新产品怎么直接调用？
> 证据：`依据/外部查证-20260919/08～12`。所有官网在本会话被代理拦截，事实来自官方 GitHub 仓库源码与 npm 发布包实物；标「未能核实」的条目等有网络的同事复核。真机与真实工程接入本轮未做。

## 0｜先说结论

1. **不自研组件。** 每个端选一个成熟生态当主库；「部门自己的一套」＝ `tokens.json`（已有）＋ 各库的**主题桥接文件**（由脚本生成）＋ **选用清单**（七类组件 × 端，写明用哪个上游组件、禁用哪些）＋ 样板页。组件本体全部来自上游，升级只改桥接，不碰组件源码。
2. **小程序端：首选 tdesign-miniprogram（腾讯 TDesign）。** 它是本轮查到的唯一一套「Web、H5、小程序共用同名设计变量（`--td-*`，179 个三端同名）」的大厂生态，七类组件全覆盖，MIT，月度发版；换主色只需在 `app.wxss` 写 `page { --td-brand-color: … }`。备选 Ant Design Mini（自带表单校验，但微信端插槽受限）；WeUI 小程序版只作「与微信原生一模一样」的补位；Vant Weapp 近 23 个月未发版，只作回退并标「维护停滞」。
3. **Web 端取决于一个决策：sales-web 现在没有任何前端框架（页面从小程序源码生成，`<script defer>` 引 vendor），是否引入 React。**
   - **不引入（路线 A，推荐先做）：** 保持无框架，引入 **Web Awesome 3.x**（Shoelace 的正式继任者，MIT；Shoelace 本体已停更，不要选它）做按钮、输入、选择、弹窗、抽屉、提示；表格与筛选栏用原生元素＋现行规范 CSS；日期继续用现有 flatpickr。主题只需把 `--ui-*` 映射到 `--wa-color-brand-*`。备选 TDesign Web Components（刚拆包、组件少，不作整站底座）。
   - **引入 React（路线 B）：** 「飞书的组件」在开源世界只有 **Semi Design**（字节跳动开源、React 专用、无小程序版）；同档还有 **Ant Design 6** 与 **TDesign React**。三者主题机制都友好（全部走 CSS 变量或一份配置）。Semi 与飞书同源、最有「飞书感」；TDesign 与小程序同名变量、一份桥接两端生效；antd 生态最大。建议先用 Semi 在「任务工作台」一页做**岛屿式**样板（在现有页面一个容器里单独挂 React），测体积与冲突，再决定是否扩大。
   - **不做整站 React 重写（路线 C）**，直到 Web 工程进仓库、第一批模块按 A 或 B 验收。
4. **「最多微调」＝ 只生成主题变量桥接文件。** 本轮已把桥接做成 `02-设计变量与同步链路/bridges.json`（源）→ `dist/bridge-*.css／.wxss／.json`（产物），由 `build-tokens.mjs` 生成，`check.mjs` 顺带跑。主色十档色阶（各库都要）由脚本按 Ant Design 开源算法从 `--ui-primary` 派生，标「建议、待官方生成器复核」。

## 2｜七类组件的选用清单（推荐主库下，建议）

| 规则 | 组件类 | 小程序：tdesign-miniprogram | Web 路线 A：Web Awesome | Web 路线 B：Semi | 状态要求（C-06／C-07） |
|---|---|---|---|---|---|
| C-01 | 按钮 | t-button（theme、loading、disabled、block） | wa-button（variant、loading、disabled） | Button（type、theme、loading、disabled） | 处理中防重复；禁用说原因 |
| C-02 | 输入与校验 | t-input、t-textarea ＋ t-form（rules） | wa-input、wa-textarea ＋ 原生 Constraint Validation；错误就地显示 | Input、TextArea ＋ Form（async-validator，可静默校验） | 标签常显、错误就地、保留输入 |
| C-03 | 选择器 | t-picker、t-date-time-picker、t-cascader、t-tree-select | wa-select（单／多选）；日期沿用 flatpickr；级联用两级 wa-select | Select、Cascader、DatePicker、TreeSelect | 加载中、无匹配、禁用 |
| C-04 | 筛选栏 | t-dropdown-menu ＋ t-tag（可选中） | 原生元素＋规范 CSS（筛选片 `.ui-chip`） | Tag、Dropdown、Space | 紧邻结果、显示已选与数量、可清除 |
| C-05 | 列表与表格 | t-cell／t-cell-group、t-list（表格类只在桌面） | 原生 `<table>`＋规范 CSS；列表行按样板 | Table、List | 字段与顺序统一；桌面不以卡片替代列表 |
| C-06 | 数据与反馈状态 | t-loading、t-skeleton、t-empty、t-toast、t-result | wa-spinner、wa-skeleton、wa-callout、toast（wa-callout ＋ 自建队列）；空状态按样板 | Spin、Skeleton、Empty、Toast、Notification | 四态齐全：加载中、空（说原因）、失败（可重试不丢条件）、无权限（不露对象名） |
| C-07 | 弹窗与展开 | t-dialog、t-popup、t-drawer、t-collapse | wa-dialog、wa-drawer、wa-details | Modal、SideSheet、Collapse | Esc 可关、焦点回触发点；手机整页进入而非弹窗（X-03） |

禁用清单（建议）：不在业务页面里混用两套小程序库；不用上游的「卡片堆叠」替代桌面列表（C-05）；不用上游默认主色与默认圆角（一律走桥接）。

## 3｜「最多微调」怎么做：主题桥接

原则：**不 fork、不改上游源码、不写第二套变量名**。只维护一份「上游变量 ← 部门变量」的映射，由脚本生成各库要的文件：

```
02-设计变量与同步链路/
  tokens.json          部门变量源（已有，53 个 --ui-*）
  bridges.json         桥接映射源（本轮新增，建议）：每个上游库一段，写「上游变量名 → {ui.xxx} 或派生色阶」
  palette.mjs          主色十档派生（移植 Ant Design 开源算法，与官方 blue 色阶逐档一致；建议）
  build-tokens.mjs     生成 dist/：design-tokens.*（已有）＋ bridge-tdesign.wxss、bridge-tdesign.css、bridge-semi.css、bridge-antd.theme.json、桥接说明.md（本轮已生成）
  check-tokens.mjs     校验桥接引用的 --ui-* 存在；产品仓库装了 tdesign-miniprogram 后再校验上游变量名是否存在于该版本
```

本轮产物（建议，未在真机与真实工程验证）：

| 产物 | 给谁 | 条数 | 引入方式 |
|---|---|---|---|
| `dist/bridge-tdesign.wxss` | 小程序 tdesign-miniprogram | 63 | `app.wxss` 头两行 `@import "./design-tokens.wxss"; @import "./bridge-tdesign.wxss";` |
| `dist/bridge-tdesign.css` | Web tdesign-react／vue、TDesign Web Components | 63（同一份映射） | 在 `design-tokens.css` 之后引入 |
| `dist/bridge-semi.css` | Web Semi Design | 35 | 在 `semi.min.css` 与 `design-tokens.css` 之后引入；只做浅色 |
| `dist/bridge-antd.theme.json` | Web Ant Design 6 | 26 | `<ConfigProvider theme={…}>`，antd 自行派生色阶 |
| Web Awesome | — | 0 | 品牌色阶变量名未能核实，拿到官方 `themes/default.css` 后补 |

逐条映射与每条的注意事项见 `02-设计变量与同步链路/dist/桥接说明.md`（生成物）与依据 12。

- **十档色阶**：TDesign、Semi、Ant Design、Web Awesome 都要主色的 10 档梯度，部门 `tokens.json` 只有 blue 4 档。脚本按 Ant Design 开源的色板算法（`@ant-design/colors` 的 generate，HSV 分步）从 `--ui-primary` 派生 10 档，写进桥接文件；状态「建议，待用各库官方生成器复核」（Semi 的算法未开源，只有在线 DSM）。
- **只改颜色、字号、圆角、控件高度、间距**这些变量；组件的结构、交互、动效保持上游默认。
- **校验**：`check-tokens.mjs` 校验桥接文件里引用的 `--ui-*` 都存在；上游变量名是否存在于锁定版本，待产品仓库装上该库后再校验（本轮未装，脚本会如实打印「跳过」）。
- **映射的硬边界**（依据 12）：Semi 运行时只有颜色、圆角、阴影、遮罩是 CSS 变量，字号／控件高／间距是构建期 Sass 变量，桥接管不到（控件高 36 对 Semi 默认 32，要么接受默认，要么构建期覆盖）；TDesign 小程序变量默认 rpx，桥接按 X-09 写 px，真机核对；两库都没有「筛选栏」复合组件，需一个只拼装上游组件的薄包装；小程序 t-table 在微信端单元格只能是文本，手机一律用 t-cell 行。

## 4｜接入步骤（每端；标「需授权」的会改真实业务工程，等你点头）

**小程序（tdesign-miniprogram）**
1. 需授权：`frontend/miniprogram` 下 `npm init`、`npm i tdesign-miniprogram -S --production`，开发者工具「构建 npm」并勾选「将 JS 编译成 ES5」；`project.config.json` 打开 npm 支持。
2. 需授权：删除 `app.json` 的 `"style": "v2"`，回归检查原生 button／input 外观；最低基础库设为 2.12.0 以上。
3. 需授权：`app.wxss` 头两行 `@import "./design-tokens.wxss"; @import "./bridge-tdesign.wxss";`；`app.json` 的 window／tabBar 颜色按 `dist/miniprogram-app.tokens.json` 改（第一张待办变更）。
4. 页面按 `usingComponents` 引入 `t-*`，先做「客户列表→详情」一页，填页面验收单，真机验证 `page { --td-* }` 覆盖生效、深色分支不误触发、px 与 rpx 观感一致。

**Web 路线 A（Web Awesome）**
1. 把 npm 包内 `dist-cdn/` 自托管到 `assets/vendor/webawesome-3.x/` 并写 SOURCE.json（CDN 在本会话不可达，公司网络待复核）；只引 `themes/default.css` 与 loader，**不引 `native.css`**。
2. 引 `dist/design-tokens.css` 与 `dist/bridge-webawesome.css`。
3. 逐页替换控件：先按钮、输入、选择、弹窗、抽屉、提示；表格与筛选栏保持原生；日期保持 flatpickr。
4. 先做「客户列表→详情」与「任务工作台」，填验收单。

**Web 路线 B（岛屿式 React ＋ Semi，样板）**
1. 需授权立项：Vite ＋ React 18（或 19 ＋ semi-ui-19）；在「任务工作台」右侧详情容器 `createRoot` 挂载。
2. 引 `dist/bridge-semi.css`（覆盖 `--semi-blue-0～9` 等）；有网络时用 Semi DSM 以 #2863CD 生成主题包对照复核。
3. 样板必须量三件事：首屏 JS 体积、与现有弹层／z-index 的冲突、返回列表是否保留筛选与位置。

## 5｜需要你决定的事（最多三件）

| 事项 | 影响 | 建议 |
|---|---|---|
| Web 端是否引入 React | 决定 Web 主库是 Web Awesome（无框架）还是 Semi／antd／TDesign React；引入意味着新增 Node 构建链与两套组件并存期 | 先按路线 A 起步；同时授权一个 Semi 岛屿样板，量完数据再定 |
| 小程序主库定 tdesign-miniprogram | 需开 npm 构建、删 `"style": "v2"`、基础库 2.12.0；改真实业务工程 | 定它；先做客户页一页并真机验证 |
| 「飞书感」要不要作为硬要求 | 若要，Web 只有 Semi（React）一条路；若只要「统一、克制」，路线 A 靠部门变量与规则也能达到 | 不作硬要求，按业务效率选 |

### 细项待定（不阻塞，采用前定；编号沿用依据 12）

- D-2 若引入 React：岛屿式 UMD（react 18 ＋ semi-ui 锁版）先做样板，还是直接建 Vite 工程；React 19 暂缓。
- D-3 控件高度：接受 Semi 默认 32／40 并把 V-03 的 36 改 32，还是坚持 36 并构建期覆盖。
- D-4 主色十档由谁生成：本轮按 Ant Design 算法派生；有网络的同事用 Semi DSM／TDesign 主题生成器复核差异后决定是否写回 `tokens.json`。
- D-5 C-03 规则文本里的「SalesSelect、SalesDatePicker」改为上游组件名；多选是「点击应用」还是「选中即生效」。
- D-7 小程序桥接单位 px 还是 rpx（建议 px，真机定稿）。
- D-8 交付形态：内部 npm 包（变量＋桥接）＋ 模板仓库（锁版 usingComponents、选用与禁用清单、样板页）；是否同时产出 Semi DSM 主题包。
- D-10 暗色模式是否纳入本期（建议不纳入，只维护浅色）。
