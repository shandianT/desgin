# 组件生态选型：用成熟的大厂组件，只做主题微调

> 这份文档回答三个问题：不自己造组件，用哪家的？只改颜色字号，怎么变成部门自己的一套？以后新产品怎么直接拿来用？
> 证据在 `依据/外部查证-20260919/08～12`。查证时各家官网都被代理拦截，事实取自官方 GitHub 仓库源码与 npm 发布包。哪些没核实、哪些没做，集中写在第 6 节。

## 0｜结论

不自研组件。每个端选一个成熟生态当主库，组件本体全部来自上游。升级只改桥接，不碰组件源码。部门自己的一套由下面几样组成：

- 已有的 `tokens.json`。
- 各上游库的主题桥接文件，由脚本生成。
- 选用清单，写明七类组件在每个端用哪个上游组件、禁用哪些。
- 样板页。

小程序首选 tdesign-miniprogram，也就是腾讯的 TDesign。查到的大厂生态里，只有它在 Web、H5、小程序三端共用同名设计变量 `--td-*`，三端同名的有 179 个。七类组件全覆盖，MIT 许可，每月发版。换主色只需在 `app.wxss` 写 `page { --td-brand-color: … }`。备选是 Ant Design Mini，它自带表单校验，但微信端插槽受限。WeUI 小程序版只用来补与微信原生一模一样的位置。Vant Weapp 近 23 个月没有发版，只作回退，登记时标维护停滞。

Web 端要先做一个决策。sales-web 现在没有任何前端框架，页面从小程序源码生成，用 `<script defer>` 引 vendor。要不要引入 React，决定了 Web 主库选谁。

路线 A 不引入 React，先做这条。保持无框架，引入 Web Awesome 3.x 做按钮、输入、选择、弹窗、抽屉、提示。它是 Shoelace 的正式继任者，MIT 许可。Shoelace 本体已停更，不要选它。表格与筛选栏用原生元素加现行规范的 CSS，日期继续用现有的 flatpickr。主题只需把 `--ui-*` 映射到 `--wa-color-brand-*`。备选是 TDesign Web Components，刚拆包、组件少，不作整站底座。

路线 B 引入 React。开源世界里，飞书的组件只有 Semi Design 一家，字节跳动开源，React 专用，没有小程序版。同档还有 Ant Design 6 与 TDesign React。三者主题机制都友好，全部走 CSS 变量或一份配置。Semi 与飞书同源，最有飞书感。TDesign 与小程序变量同名，一份桥接两端生效。antd 生态最大。先用 Semi 在任务工作台一页做岛屿式样板，也就是在现有页面的一个容器里单独挂 React，量体积与冲突，再决定要不要扩大。

路线 C 是整站 React 重写，不做。等 Web 工程进了仓库、第一批模块按 A 或 B 验收之后再议。

只做主题微调，意思是只生成主题变量的桥接文件。桥接的源是 `02-设计变量与同步链路/bridges.json`，产物是 `dist/bridge-*.css／.wxss／.json`，由 `build-tokens.mjs` 生成，`check.mjs` 顺带跑。各库都要主色的十档色阶，脚本按 Ant Design 开源算法从 `--ui-primary` 派生。这一步的状态是建议，等官方生成器复核。

## 1｜候选库对照（按端）

七类组件指规则 C-01 按钮、C-02 输入与校验、C-03 选择器、C-04 筛选栏、C-05 列表与表格、C-06 数据与反馈状态、C-07 弹窗与展开。版本与日期取自 npm registry，查证日期 2026-09-19。官网内容没有核实，见第 6 节。

各家的缺口与风险：

- tdesign-miniprogram：需开 npm 构建，现在 `project.config.json` 的 nodeModules 为 false。须删 `app.json` 的 `"style": "v2"`。最低基础库 2.12.0。变量值单位是 rpx，我们按 X-09 传 px，要真机核对。
- Ant Design Mini：定位支付宝优先。微信端无作用域插槽，Table、Grid、Collapse、IndexBar 受限。默认主色 #1677FF 恰与小程序现状一致。
- Vant Weapp：有维护停滞风险，C-02 校验要自写。
- WeUI 小程序版：组件太少，只补 navigation-bar、half-screen-dialog 这类位置，不与主库混用同一页。
- Semi Design、Arco Mobile、Web Awesome：都没有小程序版本。Semi 官方 FAQ 说暂无计划，Arco Mobile 仅有 H5。

各家的缺口与风险：

- Web Awesome：不要引 `native.css`，它会做全局重置。CDN 可达性还没复核，可以自托管到 `assets/vendor/`。
- TDesign Web Components：只有 37 star，组织非主仓，定位桌面端。
- Semi Design：十档派生算法未开源，只在 DSM 站上有。UMD 全量 gzip 约 1MB。组件级 Sass 变量只能构建期改。
- Ant Design 6：无小程序同名变量。
- TDesign React 与 Vue3：没有记录到缺口。
- Arco Design：Vue 版节奏偏慢。Arco Mobile 包内 license 字段是 ISC，与文件里的 MIT 不一致。

现有 vendor 里的 tom-select 2.6.2、flatpickr 4.6.13、echarts 6.1.0 许可宽松，可与上面任一方案并存。先把它们的配色改为读 `--ui-*`。

## 2｜七类组件的选用清单

按推荐主库列出，状态是建议。

| 规则 | 组件类 | 小程序：tdesign-miniprogram | Web 路线 A：Web Awesome | Web 路线 B：Semi | 状态要求（C-06／C-07） |
|---|---|---|---|---|---|
| C-01 | 按钮 | t-button（theme、loading、disabled、block） | wa-button（variant、loading、disabled） | Button（type、theme、loading、disabled） | 处理中防重复；禁用说原因 |
| C-02 | 输入与校验 | t-input、t-textarea ＋ t-form（rules） | wa-input、wa-textarea ＋ 原生 Constraint Validation；错误就地显示 | Input、TextArea ＋ Form（async-validator，可静默校验） | 标签常显、错误就地、保留输入 |
| C-03 | 选择器 | t-picker、t-date-time-picker、t-cascader、t-tree-select | wa-select（单／多选）；日期沿用 flatpickr；级联用两级 wa-select | Select、Cascader、DatePicker、TreeSelect | 加载中、无匹配、禁用 |
| C-04 | 筛选栏 | t-dropdown-menu ＋ t-tag（可选中） | 原生元素＋规范 CSS（筛选片 `.ui-chip`） | Tag、Dropdown、Space | 紧邻结果、显示已选与数量、可清除 |

| C-06 | 数据与反馈状态 | t-loading、t-skeleton、t-empty、t-toast、t-result | wa-spinner、wa-skeleton、wa-callout、toast（wa-callout ＋ 自建队列）；空状态按样板 | Spin、Skeleton、Empty、Toast、Notification | 四态齐全：加载中、空（说原因）、失败（可重试不丢条件）、无权限（不露对象名） |

禁用清单，状态同样是建议：

- 不在业务页面里混用两套小程序库。
- 不用上游的卡片堆叠替代桌面列表，见 C-05。
- 不用上游默认主色与默认圆角，一律走桥接。

## 3｜主题桥接怎么做

原则是不 fork、不改上游源码、不写第二套变量名。只维护一份映射，把上游变量名指向部门变量名，由脚本生成各库要的文件：

```
02-设计变量与同步链路/
  tokens.json          部门变量源（已有，53 个 --ui-*）
  bridges.json         桥接映射源（新增，建议）：每个上游库一段，写「上游变量名 → {ui.xxx} 或派生色阶」
  palette.mjs          主色十档派生（移植 Ant Design 开源算法，与官方 blue 色阶逐档一致；建议）
  build-tokens.mjs     生成 dist/：design-tokens.*（已有）＋ bridge-tdesign.wxss、bridge-tdesign.css、bridge-semi.css、bridge-antd.theme.json、桥接说明.md（已生成）
  check-tokens.mjs     校验桥接引用的 --ui-* 存在；产品仓库装了 tdesign-miniprogram 后再校验上游变量名是否存在于该版本
```

生成的产物如下，状态是建议：

| 产物 | 给谁 | 条数 | 引入方式 |
|---|---|---|---|
| `dist/bridge-tdesign.wxss` | 小程序 tdesign-miniprogram | 63 | `app.wxss` 头两行 `@import "./design-tokens.wxss"; @import "./bridge-tdesign.wxss";` |
| `dist/bridge-tdesign.css` | Web tdesign-react／vue、TDesign Web Components | 63（同一份映射） | 在 `design-tokens.css` 之后引入 |
| `dist/bridge-semi.css` | Web Semi Design | 35 | 在 `semi.min.css` 与 `design-tokens.css` 之后引入；只做浅色 |
| `dist/bridge-antd.theme.json` | Web Ant Design 6 | 26 | `<ConfigProvider theme={…}>`，antd 自行派生色阶 |
| Web Awesome | — | 0 | 品牌色阶变量名未能核实，拿到官方 `themes/default.css` 后补 |

逐条映射与每条的注意事项见 `02-设计变量与同步链路/dist/桥接说明.md`，它是生成物，另见依据 12。

十档色阶：TDesign、Semi、Ant Design、Web Awesome 都要主色的 10 档梯度，部门 `tokens.json` 只有 blue 4 档。脚本按 Ant Design 开源的色板算法从 `--ui-primary` 派生 10 档，写进桥接文件。算法就是 `@ant-design/colors` 的 generate，按 HSV 分步。这一步是建议，等各库官方生成器复核。Semi 的算法未开源，只有在线 DSM。

桥接只改颜色、字号、圆角、控件高度、间距这些变量。组件的结构、交互、动效保持上游默认。

校验由 `check-tokens.mjs` 做，它检查桥接文件里引用的 `--ui-*` 都存在。上游变量名是否存在于锁定版本，等产品仓库装上该库后再校验，装之前脚本会打印跳过。

映射有几条硬边界，见依据 12：

- Semi 运行时只有颜色、圆角、阴影、遮罩是 CSS 变量。字号、控件高、间距是构建期 Sass 变量，桥接管不到。控件高 36 对 Semi 默认 32，要么接受默认，要么构建期覆盖。
- TDesign 小程序变量默认 rpx，桥接按 X-09 写 px，要真机核对。
- 两库都没有筛选栏这种复合组件，需要一个只拼装上游组件的薄包装。
- 小程序 t-table 在微信端单元格只能是文本，手机一律用 t-cell 行。

## 4｜接入步骤

标了需授权的步骤会改真实业务工程，等授权后再做。

### 小程序：tdesign-miniprogram

1. 需授权。在 `frontend/miniprogram` 下 `npm init`、`npm i tdesign-miniprogram -S --production`。开发者工具里点构建 npm，勾选将 JS 编译成 ES5。`project.config.json` 打开 npm 支持。
2. 需授权。删除 `app.json` 的 `"style": "v2"`，回归检查原生 button 与 input 的外观。最低基础库设为 2.12.0 以上。
3. 需授权。`app.wxss` 头两行写 `@import "./design-tokens.wxss"; @import "./bridge-tdesign.wxss";`。`app.json` 的 window 与 tabBar 颜色按 `dist/miniprogram-app.tokens.json` 改，这是第一张待办变更。
4. 页面按 `usingComponents` 引入 `t-*`。先做客户列表到详情这一页，填页面验收单。真机验证 `page { --td-* }` 覆盖生效、深色分支不误触发、px 与 rpx 观感一致。

### Web 路线 A：Web Awesome

1. 把 npm 包内 `dist-cdn/` 自托管到 `assets/vendor/webawesome-3.x/`，写 SOURCE.json。CDN 查证时不可达，公司网络能否访问还没复核。只引 `themes/default.css` 与 loader，不引 `native.css`。
2. 引 `dist/design-tokens.css` 与 `dist/bridge-webawesome.css`。
3. 逐页替换控件，先换按钮、输入、选择、弹窗、抽屉、提示。表格与筛选栏保持原生，日期保持 flatpickr。
4. 先做客户列表到详情与任务工作台两页，填验收单。

### Web 路线 B：岛屿式 React 加 Semi，先做样板

1. 需授权立项。用 Vite 加 React 18，或 React 19 加 semi-ui-19。在任务工作台右侧详情容器里 `createRoot` 挂载。
2. 引 `dist/bridge-semi.css`，覆盖 `--semi-blue-0～9` 等。有网络时用 Semi DSM 以 #2863CD 生成主题包，对照复核。
3. 样板要量清楚首屏 JS 体积、与现有弹层和 z-index 的冲突、返回列表是否保留筛选与位置。

## 5｜需要决定的事

| 事项 | 影响 | 建议 |
|---|---|---|
| Web 端是否引入 React | 决定 Web 主库是 Web Awesome（无框架）还是 Semi／antd／TDesign React；引入意味着新增 Node 构建链与两套组件并存期 | 先按路线 A 起步；同时授权一个 Semi 岛屿样板，量完数据再定 |
| 小程序主库定 tdesign-miniprogram | 需开 npm 构建、删 `"style": "v2"`、基础库 2.12.0；改真实业务工程 | 定它；先做客户页一页并真机验证 |
| 飞书感要不要作为硬要求 | 若要，Web 只有 Semi（React）一条路；若只要统一、克制，路线 A 靠部门变量与规则也能达到 | 不作硬要求，按业务效率选 |

### 细项待定

不阻塞，采用前定。编号沿用依据 12。

- D-2 若引入 React：先用岛屿式 UMD 做样板，react 18 加 semi-ui 锁版，还是直接建 Vite 工程。React 19 暂缓。
- D-3 控件高度：接受 Semi 默认 32 与 40，把 V-03 的 36 改 32，还是坚持 36 并在构建期覆盖。
- D-4 主色十档由谁生成：现在按 Ant Design 算法派生。有网络的同事用 Semi DSM 或 TDesign 主题生成器复核差异，再决定是否写回 `tokens.json`。
- D-5 C-03 规则文本里的 SalesSelect、SalesDatePicker 改为上游组件名。多选是点击应用才生效，还是选中即生效。
- D-7 小程序桥接单位用 px 还是 rpx。倾向 px，真机定稿。
- D-8 交付形态：内部 npm 包放变量与桥接，模板仓库放锁版 usingComponents、选用与禁用清单、样板页。是否同时产出 Semi DSM 主题包。
- D-10 暗色模式这一期做不做。倾向不做，只维护浅色。
- D-11 两处连带：`--ui-muted` 映射到 `--td-text-color-placeholder` 会改深占位文字；`--ui-overlay` 没有映射 `--td-mask-active`，后者同时是 toast 底色。

### 名词解释

- Web Components：浏览器原生的自定义标签，不依赖框架。
- 岛屿式挂载：在现有页面的一个容器里单独启动 React。
- Shadow DOM：组件自带的隔离样式盒子，外部 CSS 进不去，但 CSS 变量能穿透。
- UMD：可以直接用 `<script>` 引入的打包格式。
- 桥接文件：把上游库的变量名指向部门变量名的一小段 CSS。
