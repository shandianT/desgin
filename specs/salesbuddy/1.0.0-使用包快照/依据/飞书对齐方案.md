# 飞书对齐方案

**状态：方案草案。** 本文整理当前讨论方向，尚未完成整套页面与交互对齐，不替代 [SalesBuddy Web 设计规范 V1](../依据/Web设计规范.md)。本轮授权为集中整理交付目录。

## 目标

让用户能够快速定位信息、理解状态并连续处理业务。以飞书的业务操作方式作为主要参考，结合销售管理自己的对象、流程、权限与品牌表达形成规范。

## 参考对象与输出

| 场景 | 参考对象 | 要明确的项目规则 |
|---|---|---|
| 客户、商机、拜访列表 | 飞书多维表格 | 搜索、筛选、排序、分组、展示列及视图关系 |
| 任务工作台 | 飞书任务 | 我负责的、我发起的、负责人、期限与处理入口 |
| 对象详情与连续处理 | 飞书项目 | 列表和详情关系、半屏/全屏、关联信息、返回位置 |
| 规范文档阅读 | 飞书文档 | 目录、标题层级、内容分块、中文阅读 |
| 基础视觉与组件 | Semi 官方列出的飞书 Universe Design 主题 | 配色、字级、边界、控件尺寸和交互状态；映射到现有组件 |

## 项目设计原则建议

以下为本项目拟采用的规则，不是飞书官方原则原文。

1. **找得到：** 导航名称稳定，搜索和筛选紧邻结果，授权范围与当前条件可见。
2. **看得懂：** 对象、状态、负责人、时间位置稳定；中文文案说明动作与结果。
3. **少跳转：** 简短详情就地查看；关闭后保留筛选、选中对象和滚动位置。
4. **可恢复：** 失败保留输入，重试防止重复提交，未保存修改得到保护。
5. **可追溯：** 任务能找到来源，状态变化有依据，关联客户与商机按权限访问。

## 先做三个样板页

| 样板 | 关键路径 | 关键异常与检查点 |
|---|---|---|
| 商机列表 | 搜索 → 筛选 → 查看详情 → 返回列表 | 无匹配结果；返回后条件与位置保留 |
| 任务工作台 | 我负责的 → 今天到期 → 查看详情 → 处理 → 下一条 | 处理失败保留内容，不重复创建或提交 |
| 拜访录入与核对 | 关联对象 → 填写 → 核对质检 → 人工确认 → 保存 | 缺字段或质检失败能定位问题，原输入保留 |

详细业务方案继续引用原有 [Web 交互重构建议](../依据/Web交互重构建议.md)，其中的建议、已实现部分与接口待确认项按原文分别说明。

## 与现有业务保持一致

- 客户、商机、拜访和任务分别表达；拜访中的“下一步计划”只有正式创建成功后才成为任务。
- 接受任务不等于完成任务。权限与状态转换沿用真实业务契约，不能因为参考其他产品而增加不存在的动作。
- 简短任务信息可用侧栏；复杂拜访核对需要完整编辑空间。
- Web 和小程序共享业务含义与接口规则，各自使用适合屏幕的布局。

## 规范的记录格式

每项按“参考来源 → 适用场景 → 具体规则 → 可交互示例 → 验收方法”记录。来自官方文档、实际页面观察及本项目新增建议应分别标明。

先完成样板体验核对，再把采用的规则合入现行主规范；同步样式变量、组件状态、页面模板和验收清单。Apple 手册继续作为视觉参考资料保留。
