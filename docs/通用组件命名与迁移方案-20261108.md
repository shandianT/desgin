# 通用组件命名与迁移方案

## 目标

让不同产品能够复用部门组件，同时不迫使现有 SalesBuddy 一次性重写。

## 分层

| 层 | 负责什么 | 示例 |
|---|---|---|
| 部门规范 | 通用视觉、状态和交互规则 | Token、空态、错误态、表单、列表 |
| 部门组件 | 通用组件和语义 API | `DsStatusTag`、`DsStatePanel`、`DsTable` |
| 项目适配 | 品牌、导航、文案、功能开关、路由 | `projects/salesbuddy/project.config.json` |
| 业务适配 | 接口、权限、数据和正式状态 | 产品工程自己的 adapter |
| 产品专属组件 | 只服务一个项目的组合件 | SalesBuddy BattleMap、销售排名 |

## Web 组件迁移

现有 `Sb*` 导出暂时保留，并增加 `Ds*` 别名：

```jsx
import { DsProvider, DsStatusTag, DsStatePanel } from '@shandiant/ui-react';

<DsProvider>
  <DsStatePanel state="empty" title="暂无记录" />
  <DsStatusTag tone="watch" label="需关注" />
</DsProvider>
```

`Sb*` 只作为兼容入口，不再用于新产品代码。连续两个小版本没有新使用后，再考虑主版本移除。

## 小程序组件迁移

现有 `sb-*` 组件先保持兼容。0.12.0 已新增一批 `ds-*` 目录；新的通用组件继续使用 `ds-*` 命名，并保持与 Web 相同的语义属性：

- `ds-status-tag` 对应 `tone / label / reason`；
- `ds-state-panel` 对应 `state / title / description / retry / clear`；
- `ds-filter-bar` 对应 `scope / options / value / resultCount`；
- `ds-list-row` 对应 `name / summary / status / time`。

端侧实现可以不同，但同一字段的含义、状态和事件必须一致。

## 产品接入示例

```text
产品工程
├── project.config.json
├── adapters/
│   └── salesbuddy.js
├── pages/
│   ├── home/
│   └── detail/
└── package.json
    └── @shandiant/ui-react
```

产品页面只负责把业务数据映射成组件属性：

```jsx
<DsListRow
  name={customer.name}
  summary={customer.owner}
  status={{ tone: customer.statusTone, label: customer.statusLabel }}
  time={customer.lastContactAt}
/>
```

组件不读取数据库，也不判断客户是否“向好”或“转差”。

## 验收要求

新增项目至少验证：

1. 不复制 `specs/salesbuddy/`；
2. 只通过配置覆盖品牌和导航；
3. 通过业务 adapter 提供数据；
4. Web 和小程序使用相同语义字段；
5. 开发环境和生产环境使用不同数据库连接；
6. 不把数据库密码、Token 和真实业务数据提交到设计仓库。
